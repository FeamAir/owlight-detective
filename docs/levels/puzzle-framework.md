# Каркас головоломок (puzzle framework)

Статус: черновик v1, левел-дизайн. Документ не зависит от сюжета: здесь правила, типы, шаблоны и распределение. Конкретные головоломки описываются по шаблону из раздела 6 в отдельных файлах `docs/levels/`.

Обязательные требования брифа (`docs/00-brief.md`), на которые опирается документ:
- не меньше 100 головоломок, разные типы и сложность, есть многоэтапные;
- несколько дальних связей (подсказка в начале игры, применение ближе к концу);
- три уровня сложности, при этом **сюжет и порядок прохождения на всех уровнях одинаковы**;
- RU и EN: та же логика, та же сложность, тот же ответ;
- у каждой головоломки разделены механика, тестовые значения и релизные значения; значения хранятся как параметры;
- мобильный формат (Android): сенсорный экран, короткие сессии;
- всё оригинальное: никаких узнаваемых головоломок из существующих игр.

Условные обозначения:
- **Л / Н / С**: лёгкий / нормальный / сложный уровень.
- **ID головоломки**: `PZ-<глава>-<номер>`, например `PZ-3-07`. Дальние связи: `LL-01`... Улики и предметы: `CL-...`, `IT-...`, локации: `LOC-...`.
- **Сложность (рейтинг)**: 1–5, оценивается для уровня Н. На Л ощущается примерно на 1 ниже, на С на 1 выше.
- **Класс перевода**: A / B / C / D (раздел 4).

---

## 1. Общие принципы

1. **Честность.** Всё, что нужно для решения, игрок может увидеть, прочитать или получить в игре до момента решения. Никаких «угадай, что задумал автор». Решение проверяется одним вопросом: «может ли внимательный игрок объяснить, почему ответ именно такой?».
2. **Одна головоломка — одна главная идея.** Многоэтапные головоломки собираются из этапов, у каждого этапа своя идея и своя точка сохранения.
3. **Подсказка и замок разнесены.** Источник подсказки и место применения обычно в разных объектах или локациях (бриф: «подсказки разбросаны, их нужно находить и соединять»). Исключение: обучающие головоломки главы 1.
4. **Значения — параметры.** Ни одно число, символ или комбинация не пишется в тексты и графику «намертво». Тексты-подсказки делаются шаблонами (`Сейф открывается кодом {code}`), графика с числами делается слоями или вариантами (раздел 6.3).
5. **Без наказания временем и без тупиков.** Нет таймеров с проигрышем, нет блокировки замка после ошибок, нет безвозвратно теряемых улик. Ошибка максимум сбрасывает текущую попытку.
6. **Без пиксель-хантинга.** Активная зона не меньше 48 dp (около 9 мм) с каждой стороны; мелкий предмет получает увеличенную невидимую зону касания. Важные предметы визуально отличимы (контраст, свет, лёгкий блик), а не спрятаны в шуме.
7. **Прерываемость.** Состояние любой головоломки сохраняется при сворачивании приложения. Головоломки дольше 5 минут (на Н) делятся на этапы с автосохранением.
8. **Доступность.** Цвет всегда дублируется формой или символом. Звук всегда дублируется визуальным каналом (многие играют на телефоне без звука).
9. **Оригинальность.** Классические математические основы (перестановки, сетки, графы) допустимы, но не в узнаваемом «каноническом» виде из других игр: своя рамка, свой предмет, свои правила.

## 2. Таксономия типов (22 типа)

Для каждого типа: суть, управление на сенсорном экране, параметры (то, что меняется между тестом, релизом и уровнями сложности), ограничения на значения (что проверять при подборе релизных значений), масштабирование на Л/Н/С, класс перевода, риски.

Базовые жесты (общие для всех типов):
- **тап** — осмотр, выбор, нажатие кнопки;
- **перетаскивание** — перемещение детали, предмета из инвентаря;
- **круговой свайп** — вращение диска, кольца, ручки (с привязкой к шагам);
- **щипок** — приближение (только для осмотра; решение не должно требовать щипка);
- **долгое нажатие** — подробное описание предмета / добавить в блокнот.
Все перетаскивания имеют «магнит» (snap) к допустимым позициям.

### T01. Кодовый замок
- **Суть:** ввести код (цифры, символы, положения дисков). Код выводится из найденных подсказок.
- **Управление:** тап по кнопкам клавиатуры или вертикальный свайп по колёсам барабана; кнопка «открыть» / автопроверка при заполнении.
- **Параметры:** `code` (значение), `code_length`, `alphabet` (цифры / символы мира / цвета), `input_kind` (кнопки / барабаны / диск), `autocheck` (да/нет), `sources[]` (откуда берутся части кода).
- **Ограничения значений:** код не очевиден (не 0000, 1234, не год из той же записки, если это не замысел); при нескольких источниках каждая часть кода берётся ровно из одного места.
- **Л / Н / С:** Л — 3 знака, один источник, код записывается в блокнот автоматически, неверные позиции подсвечиваются; Н — 4 знака, 1–2 источника, без подсветки позиций; С — 4–5 знаков, 2–3 источника, части кода нужно вывести (посчитать, сопоставить), есть похожие «ложные» числа в окружении.
- **Перевод:** A (если подсказка — число/символ на предмете), B (если код выводится из текста).
- **Риски:** перебор вместо решения (на 3 цифрах перебор реален — ставить хотя бы 3 знака из 6+ вариантов или задержку анимации 0,5–1 с на попытку); неочевидный порядок частей кода — порядок обязан быть задан в подсказке (номера, стрелки, позиции).

### T02. Символьный шифр (вымышленный алфавит/знаки мира)
- **Суть:** расшифровать сообщение по ключу. Ключ (таблица соответствий) найден отдельно или собирается по частям.
- **Управление:** тап по символу в сообщении, затем выбор значения из ключа; найденное значение подставляется во все такие же символы. Отдельно — поле ответа (выбор, не ввод с клавиатуры).
- **Параметры:** `key_map` (символ → значение), `message`, `key_fragments[]` (части ключа и где лежат), `answer`, `answer_kind` (число / предмет / место на карте).
- **Ограничения значений:** ключ должен однозначно декодировать сообщение; ответ — нелингвистический (число, позиция, выбор картинки).
- **Л / Н / С:** Л — ключ целиком, сообщение короткое, автоподстановка всех одинаковых символов; Н — ключ из 2 частей, часть символов нужно вывести по контексту (не более 20 %); С — ключ из 3 частей, 30–40 % выводится по контексту, без автоподстановки.
- **Перевод:** **B, особая схема.** Предпочтительно шифр «символ → число/пиктограмма» (класс A). Если шифр буквенный — для RU и EN делается отдельный ключ и отдельный шифротекст из локализованного открытого текста; длина сообщения и доля «выводимых» символов одинаковы (±15 %); ответ одинаковый. Буквенный шифр подстановки по реальному алфавиту — только по схеме B, никогда «один шифротекст на два языка».
- **Риски:** частотный анализ разный на RU и EN (сложность может «поплыть») — тестировать оба языка; объём текста на мобильном экране — не больше 3–4 строк в одном окне.

### T03. Трафарет / наложение
- **Суть:** наложить один предмет на другой (решётку с прорезями на текст, прозрачную плёнку на карту, два чертежа друг на друга), чтобы проявилась информация.
- **Управление:** перетащить трафарет на объект, вращение кнопкой «повернуть на 90°» или круговым свайпом, привязка к сетке.
- **Параметры:** `grid_size`, `holes[]` (позиции прорезей), `base_content`, `rotations_needed` (0–3), `result`.
- **Ограничения значений:** только одно положение трафарета даёт осмысленный результат.
- **Л / Н / С:** Л — одно положение, без вращения, трафарет «защёлкивается»; Н — нужно найти верный поворот из 4; С — 2 слоя (трафарет + плёнка) или поворот + сдвиг, на базе есть правдоподобные ложные совпадения.
- **Перевод:** A, если проявляются цифры/символы/точки на карте. **Наложение на текст (прорези открывают буквы) — запрещено (D)**, т. к. зависит от конкретных букв. Допустимая замена: прорези открывают цифры или знаки в тексте.
- **Риски:** мелкая сетка на телефоне — не больше 6×6 клеток на экране.

### T04. Механизм (шестерни, рычаги, передачи, замки-механизмы)
- **Суть:** привести механизм в рабочее состояние: поставить недостающие детали, выставить рычаги, добиться передачи движения.
- **Управление:** перетаскивание деталей на оси; тап по рычагу (переключение); кнопка «запустить» с анимацией результата.
- **Параметры:** `slots[]`, `parts[]` (включая лишние), `target_state`, `levers_count`, `lever_links` (какой рычаг на что влияет).
- **Ограничения значений:** решение достижимо, проверено перебором/скриптом; нет «почти работающих» состояний, визуально неотличимых от решения.
- **Л / Н / С:** Л — 2–3 детали, лишних нет, при неверной установке деталь не встаёт; Н — 3–5 деталей, 1–2 лишних, проверка только запуском; С — 5–7 деталей, 2–3 лишних, рычаги взаимосвязаны, нужно найти схему (чертёж) в другой локации.
- **Перевод:** A.
- **Риски:** физика «на глаз» нечестна — правила механизма должны быть видимы (зубцы, стрелки на рычагах, чертёж).

### T05. Слайдер / вращение (кольца, плитки, диски)
- **Суть:** переставить плитки или повернуть кольца, чтобы собрать картинку/символ/выравнивание.
- **Управление:** свайп по ряду/кольцу; тап по плитке рядом с пустой клеткой. Кнопка «сброс» всегда доступна.
- **Параметры:** `grid` или `rings_count`, `steps_per_ring`, `linked_rings` (кольца, вращающиеся вместе), `scramble_seed`, `max_scramble_depth`.
- **Ограничения значений:** состояние решаемо (для перестановочных головоломок проверять чётность); глубина перемешивания задаётся числом ходов от решения, а не случайной перестановкой.
- **Л / Н / С:** Л — 3 кольца или сетка 3×3, перемешивание 6–8 ходов, верно стоящие элементы подсвечиваются; Н — 4 кольца / 3×3 с 12–15 ходами, без подсветки; С — 4–5 колец со связанными вращениями или 4×4, 20+ ходов, итоговая картинка известна только по подсказке из другой локации.
- **Перевод:** A.
- **Риски:** скучный механический перебор; «канонические» пятнашки узнаваемы — оформлять как предмет мира (кольца сейфа, фрагменты витража). Не больше 6 головоломок этого типа на игру.

### T06. Комбинирование предметов (инвентарь)
- **Суть:** соединить предметы между собой или применить предмет к объекту мира («взять подсказки вместе и куда-то вставить»).
- **Управление:** перетащить предмет из инвентаря на предмет / на объект сцены; в инвентаре — режим «соединить» (перетаскивание одного на другой).
- **Параметры:** `recipe[]` (входы → результат), `target_hotspot`, `decoys[]` (предметы, которые «почти подходят»), `feedback_on_wrong` (реплика героя).
- **Ограничения значений:** у каждой комбинации есть логичное объяснение в мире; на неверную комбинацию — осмысленная реплика, а не «Не работает».
- **Л / Н / С:** Л — 2 предмета, при подборе нужного предмета он подсвечивается в инвентаре, объект-цель подсвечивается; Н — 2–3 предмета, без подсветки; С — 3–4 предмета, промежуточный результат нужно ещё раз применить, неверные пары дают правдоподобные, но бесполезные реплики. Состав предметов на всех уровнях одинаков (порядок прохождения не меняется), меняется только явность.
- **Перевод:** A (реплики переводятся, логика не зависит от языка).
- **Риски:** «лунная логика» (неочевидные сочетания) — главный риск жанра. Правило: каждое сочетание должно быть подсказано хотя бы одним из трёх способов — реплика героя, изображение/описание в документе, форма предмета. Инвентарь на телефоне: не больше 8–10 предметов одновременно, лишние предметы уходят из инвентаря после использования.

### T07. Сборка из частей (обрывки, осколки, разобранный предмет)
- **Суть:** собрать целое из фрагментов: разорванное письмо, фото, разбитая табличка, разобранная шкатулка.
- **Управление:** перетаскивание фрагментов, поворот тапом (90°), магнит к правильным соседям.
- **Параметры:** `pieces_count`, `rotation_enabled`, `missing_pieces[]` (части, найденные в других локациях), `decoy_pieces`, `edge_hints` (видны ли края).
- **Ограничения значений:** у каждого фрагмента одно место; фрагменты различимы на маленьком экране.
- **Л / Н / С:** Л — 4–6 частей, без поворота, все на месте, правильные части «прилипают»; Н — 6–9 частей, поворот, 1–2 части найдены в других местах; С — 9–12 частей, поворот, 2–3 части в других локациях, 1–2 лишних фрагмента от другого предмета.
- **Перевод:** если собирается текст — **C** (нужна локализованная графика фрагментов, разрезы для RU и EN делаются по одинаковой схеме), иначе A. Форма разрывов не должна совпадать с границами слов (иначе сложность разная на языках).
- **Риски:** слишком мелкие части; более 12 частей — превращается в рутину.

### T08. Поиск предметов / наблюдательность в сцене
- **Суть:** найти в сцене предметы по списку (силуэтам, описаниям) или найти «то, что не так» (спрятанная деталь, след).
- **Управление:** тап по предмету; щипок для приближения допустим, но всё нужное различимо без него.
- **Параметры:** `targets[]`, `list_kind` (силуэты / пиктограммы / описания), `clutter_level`, `targets_count`.
- **Ограничения значений:** каждый предмет отличим от фона при нормальной яркости экрана; не меньше 48 dp зона касания.
- **Л / Н / С:** Л — 4–5 предметов, список силуэтами, после 30 с без находки предмет слегка мерцает; Н — 6–7 предметов, силуэты, без мерцания; С — 8 предметов, часть списка дана описанием-функцией («чем можно открыть письмо»), больше мусора в сцене.
- **Перевод:** A при силуэтах; B при текстовых описаниях (описание переводится, предмет тот же).
- **Риски:** пиксель-хантинг; утомляемость — не больше 6 сцен такого типа на игру, не два подряд.

### T09. Сравнение изображений (было/стало, копия/оригинал)
- **Суть:** найти различия между двумя изображениями (фото комнаты до и после, подделка картины), различия несут смысл для расследования.
- **Управление:** два изображения рядом (горизонтальная ориентация) или переключатель «до/после» по тапу; отметка различия тапом.
- **Параметры:** `differences[]`, `meaningful_differences[]` (те, что важны для сюжета), `diff_size`.
- **Л / Н / С:** Л — 3–4 крупных различия, счётчик «осталось N»; Н — 5 различий, счётчик; С — 5–6 различий, часть мелкие (но не меньше 48 dp зоны), без счётчика, нужно отметить только значимые.
- **Перевод:** A (если на изображениях нет текста), иначе C.
- **Риски:** различия на мобильном экране незаметны — тестировать на экране 5,5''.

### T10. Логическая задача (сетка дедукции)
- **Суть:** по набору утверждений определить соответствия (кто, где, когда, что). Утверждения собираются из найденных записок/показаний.
- **Управление:** таблица соответствий в блокноте: тап по клетке ставит «нет / да / пусто»; итоговый ответ — выбор карточек.
- **Параметры:** `dimensions` (например, 3×3 или 4×4×4), `facts[]`, `solution`, `facts_sources[]`.
- **Ограничения значений:** решение единственно и выводимо из фактов без угадывания — проверять решателем. Ни один факт не должен быть лишним на С (на Л/Н допустимы избыточные факты).
- **Л / Н / С:** Л — 3×3, избыточные факты, таблица сама вычёркивает очевидные следствия; Н — 4×4, необходимый минимум + 1 избыточный факт; С — 4×4×4 (три измерения), факты разбросаны по 3+ локациям, один факт косвенный (вывести из документа).
- **Перевод:** B. Утверждения пишутся отдельно для RU и EN с той же логической формой. Запрещено опираться на грамматический род («она была в саду» раскрывает пол в RU, но не всегда в EN). Имена — одинаковые на обоих языках, без значащих окончаний.
- **Риски:** перегрузка текстом — каждый факт в одну строку, не больше 8 фактов на экран.

### T11. Последовательность и порядок действий
- **Суть:** выполнить действия в правильном порядке (нажать плитки, зажечь свечи, переложить предметы) по найденной инструкции/закономерности.
- **Управление:** тапы по элементам; неверный шаг сбрасывает последовательность с явной анимацией.
- **Параметры:** `sequence[]`, `sequence_length`, `elements_count`, `reset_on_error` (весь сброс / откат на шаг), `source`.
- **Л / Н / С:** Л — 3–4 шага, инструкция прямая, верные шаги остаются подсвеченными, ошибка откатывает на 1 шаг; Н — 5–6 шагов, инструкция требует сопоставления (например, порядок по датам в документе), ошибка — полный сброс; С — 6–8 шагов, порядок выводится из 2 источников или по закономерности.
- **Перевод:** A, если порядок задан числами/символами/позициями; B, если порядок выводится из текста. **Запрещено: порядок по алфавиту, по первым буквам слов.**
- **Риски:** перебор на коротких последовательностях; непонятно, что шаг засчитан — нужен явный отклик.

### T12. Звук / музыка
- **Суть:** воспроизвести мелодию, ритм или комбинацию звуков, найденную в мире (ноты на листе, колокольчики, бой часов).
- **Управление:** тап по клавишам/колокольчикам; кнопка «послушать образец», если он есть.
- **Параметры:** `notes[]` (в виде индексов элементов, не нот реального строя), `length`, `tempo_matters` (на С — да/нет), `visual_notation` (обязательна).
- **Ограничения значений:** у каждого звука есть **визуальная пара** (цвет + форма/номер). Головоломка решается без звука.
- **Л / Н / С:** Л — 4 звука, клавиши пронумерованы так же, как запись; Н — 5–6 звуков, запись в символах мира, соответствие клавиш нужно найти; С — 7–8 звуков, запись неполная, недостающие звуки берутся из другого источника (например, бой часов в другой локации).
- **Перевод:** A.
- **Риски:** игрок без звука — визуальный канал обязателен; люди без музыкального слуха — не требовать определения высоты на слух.

### T13. Свет / тени / цвет
- **Суть:** направить луч зеркалами, смешать цветные фильтры, поставить предмет так, чтобы тень дала рисунок/число, проявить скрытые чернила.
- **Управление:** тап по зеркалу (поворот на фиксированный шаг), перетаскивание фильтра/предмета, вращение источника света круговым свайпом.
- **Параметры:** `grid`, `mirrors_count`, `filters[]`, `target`, `color_rules` (правила смешения задаются в мире, а не «школьной физикой»).
- **Ограничения значений:** цвета различимы при дальтонизме: каждый цвет имеет символ/узор; правила смешения показаны (табличка, витраж-образец).
- **Л / Н / С:** Л — 2–3 зеркала, луч видно постоянно; Н — 4–5 зеркал, 1 фильтр; С — 5–6 зеркал, 2 фильтра, цель нужно определить по подсказке, видимой только при определённом освещении.
- **Перевод:** A.
- **Риски:** цветовая слепота; яркость экрана на улице — не строить решение на тонких оттенках.

### T14. Карта и ориентация
- **Суть:** найти точку на карте/плане по описанию маршрута, координатам, сторонам света; сориентировать карту по реальной локации.
- **Управление:** карта на весь экран, перетаскивание и щипок для навигации, тап — поставить метку; вращение карты круговым свайпом.
- **Параметры:** `map_asset`, `target_point`, `route_steps[]` (шаги вида «N клеток на восток»), `landmarks[]`, `grid_labels` (цифры/символы мира).
- **Ограничения значений:** координатная сетка — цифры или символы мира, не буквы; стороны света обозначены символами (роза ветров) одинаково на RU и EN.
- **Л / Н / С:** Л — 2–3 шага маршрута, сетка подписана, верная клетка подсвечивается при приближении; Н — 4–5 шагов, нужно сориентировать карту по ориентиру; С — 5–7 шагов, часть маршрута в другом документе, карта без сетки (только ориентиры).
- **Перевод:** C для подписей на карте (локализованная графика) или подписи — символами мира; маршрут в тексте — B. **Не использовать буквенные координаты (A1, Б2): буквы RU и EN различаются.**
- **Риски:** мелкая карта на телефоне — разбивать на фрагменты с увеличением.

### T15. Анализ документов (сопоставление текстов)
- **Суть:** сопоставить несколько документов (письма, расписания, счета, дневник) и найти противоречие, факт или число.
- **Управление:** документы открываются в блокноте; режим «сравнить» — два документа рядом; тап по фрагменту выделяет его; ответ — выбор фрагментов-доказательств или ввод числа.
- **Параметры:** `documents[]`, `key_fragments[]`, `answer`, `answer_kind` (выбор фрагмента / число / карточка).
- **Ограничения значений:** ответ не зависит от формулировки (число, время, предмет, лицо). **Даты — только в однозначном формате** (месяц словом или календарь мира): «03.04» читается по-разному в RU и EN.
- **Л / Н / С:** Л — 2 документа, ключевые фрагменты выделены цветом в блокноте; Н — 2–3 документа, без выделения; С — 3–4 документа, плюс 1–2 документа с правдоподобными ложными данными.
- **Перевод:** B. Ключевые фрагменты пишутся для каждого языка отдельно, с тем же фактом; переводчик получает пометку «ключевой фрагмент, не менять число/время/имя».
- **Риски:** много текста на маленьком экране — документ не длиннее ~120 слов (RU), ключевая информация не в последней строке длинного текста; время — 24-часовой формат или аналоговые часы на картинке.

### T16. Анализ изображений (картины, фото, гравюры)
- **Суть:** найти на изображении деталь, несущую информацию: число предметов, положение стрелок часов, символ, направление взгляда, порядок фигур.
- **Управление:** открытие изображения на весь экран, щипок; тап по детали добавляет её в блокнот.
- **Параметры:** `image_asset`, `key_details[]`, `derived_value` (что извлекается), `variants` (варианты графики для разных значений).
- **Ограничения значений:** ключевая деталь видна на экране 5,5'' без максимального увеличения.
- **Л / Н / С:** Л — 1 деталь, после тапа по картине блокнот отмечает «что-то важное в нижнем углу»; Н — 1–2 детали, без отметки; С — 2–3 детали, которые нужно сопоставить (например, число свечей × положение стрелок).
- **Перевод:** A без текста; C, если на изображении надписи (локализованная версия графики обязательна).
- **Риски:** художник должен получить точное ТЗ, что именно и где изображено; значение детали — параметр (нужны варианты графики под тест и релиз).

### T17. Соединения (провода, трубы, цепи, нити на доске)
- **Суть:** соединить точки так, чтобы выполнилось условие: ток/вода дошли до цели, цепи не пересеклись, нити совпали с цветами.
- **Управление:** тап по сегменту (поворот), или проведение пальцем от точки к точке.
- **Параметры:** `grid_size`, `tiles[]`, `sources[]`, `sinks[]`, `blocked_cells[]`.
- **Ограничения значений:** решение единственно или все решения засчитываются; проверять решателем.
- **Л / Н / С:** Л — 4×4, 1 источник, подключённые сегменты светятся; Н — 5×5, 2 источника; С — 6×6, 2–3 источника, запрет пересечений, часть плиток закреплена.
- **Перевод:** A.
- **Риски:** сетка больше 6×6 на телефоне неудобна.

### T18. Весы / баланс / измерения
- **Суть:** уравновесить весы, отмерить нужный объём/вес, подобрать грузы по найденной записи.
- **Управление:** перетаскивание грузов на чаши/в сосуды; переливание тапом по сосуду-источнику, затем по сосуду-цели.
- **Параметры:** `weights[]`, `target`, `vessels[]`, `capacities[]`, `steps_limit` (нет на Л/Н).
- **Ограничения значений:** решение существует, минимальное число шагов известно (решатель).
- **Л / Н / С:** Л — 3–4 груза, шкала показывает разницу числом; Н — 4–5 грузов, шкала только «легче/тяжелее»; С — 5–6 грузов, вес одного груза нужно вывести из документа.
- **Перевод:** A. Единицы измерения — вымышленные или условные (насечки, гири с точками), чтобы не путать с фунтами/граммами.
- **Риски:** классические задачи на переливание узнаваемы — давать свою рамку и свои ёмкости.

### T19. Часы и время
- **Суть:** выставить время на часах, календаре, солнечных часах, механизме по найденному событию или расчёту.
- **Управление:** круговой свайп по стрелкам с привязкой к 5 минутам (Л/Н) или к 1 минуте (С); календарь — барабаны.
- **Параметры:** `target_time`, `snap_minutes`, `source`, `offset_rule` (например, «за 2 часа до…»).
- **Ограничения значений:** время показывается аналоговыми часами или в 24-часовом формате; не строить решение на AM/PM.
- **Л / Н / С:** Л — время дано прямо, привязка 15 мин; Н — время нужно вычислить из одного документа, привязка 5 мин; С — вычислить из 2 источников, привязка 1 мин.
- **Перевод:** A / B (если вычисление идёт из текста).
- **Риски:** формат времени в EN (12 ч) — использовать часы на картинке, а в тексте — формулировки без AM/PM.

### T20. Доска дедукции (вывод из улик)
- **Суть:** связать собранные улики в утверждения и сделать вывод (кто/как/почему). Типичная головоломка-итог эпизода или главы.
- **Управление:** доска в блокноте: перетаскивание карточек улик в слоты утверждения («[Улика] доказывает, что [вывод]»), выбор из вариантов вывода.
- **Параметры:** `slots[]`, `cards_pool[]`, `correct_links[]`, `conclusion_options[]`, `partial_feedback` (сколько слотов верно).
- **Ограничения значений:** каждая связь обоснована текстом улики; нет «хитрых» связей, понятных только автору.
- **Л / Н / С:** Л — 3 слота, в пуле только нужные карточки + 1 лишняя, сообщается, какие слоты верны; Н — 4–5 слотов, 2–3 лишние карточки, сообщается число верных слотов; С — 5–6 слотов, все карточки главы в пуле, только «верно / неверно».
- **Перевод:** B (тексты улик и выводов переводятся, логика связей та же).
- **Риски:** длинные формулировки на мобильном — карточка ≤ 8 слов.

### T21. Шкатулка / многоэтапный объект-головоломка
- **Суть:** один предмет с несколькими секретами (потайные панели, механика, замок внутри замка). Каждый этап — свой мини-тип (T01, T04, T05, T11…).
- **Управление:** предмет в 3D-подобном виде с поворотом на 4 стороны (тап по стрелкам или горизонтальный свайп), этапы раскрываются последовательно.
- **Параметры:** `stages[]` (каждый со своим типом и параметрами), `stage_checkpoints` (всегда да).
- **Л / Н / С:** Л — 2–3 этапа, после каждого этапа подсвечивается, где следующий; Н — 3–4 этапа; С — 4–5 этапов, один этап требует предмет/подсказку из другой главы (возможна дальняя связь).
- **Перевод:** зависит от этапов (класс — худший из классов этапов).
- **Риски:** длительность — каждый этап ≤ 4 мин на Н, сохранение после каждого этапа.

### T22. Метазагадка (сквозная)
- **Суть:** ответ собирается из результатов многих головоломок или из знаков, разбросанных по всей игре (например, символ из каждой главы). Решается в финале.
- **Управление:** специальная страница блокнота «Метазагадка»: найденные фрагменты добавляются автоматически (на всех уровнях — это часть честности); финальное решение — выбор/расстановка фрагментов.
- **Параметры:** `fragments[]` (и где каждый находится), `assembly_rule`, `answer`.
- **Ограничения значений:** каждый фрагмент обязательно получается по ходу основного прохождения (не прячется в необязательный угол); правило сборки подсказано в финальной локации.
- **Л / Н / С:** Л — фрагменты сразу на своих местах, нужно понять только правило; Н — фрагменты нужно расставить; С — 1–2 фрагмента нужно «прочитать» заново (их значение меняется в свете финального знания).
- **Перевод:** A (фрагменты — символы, числа, изображения).
- **Риски:** игрок не понимает, что собирает метазагадку — страница появляется в блокноте после первого фрагмента с пустыми слотами.

## 3. Три уровня сложности

### 3.1. Что не меняется никогда
- Сюжет, локации, порядок прохождения, граф прогрессии (что открывает что).
- Набор обязательных предметов и улик, места, где они лежат.
- Механика головоломки (тип и правила).
- Наличие дальних связей (на Л они просто легче находятся).

Допустимо на С: добавить **отвлекающие** объекты/документы/детали, если они не создают новых обязательных шагов и не блокируют прогресс.

### 3.2. Что меняется (общая таблица)

| Параметр | Лёгкий | Нормальный | Сложный |
|---|---|---|---|
| Число элементов (деталей, знаков, плиток) | минимум | средне | максимум |
| Число шагов / этапов | минимум, этапы объединены | средне | максимум |
| Число источников подсказки | 1 | 1–2 | 2–3 |
| Явность подсказки в мире | прямая («код 482») | требует сопоставления | требует вывода/расчёта |
| Отвлекающие детали | нет | немного, явно второстепенные | есть, правдоподобные |
| Подсветка активных зон | постоянно включена (мягкое свечение) | кнопка «лупа», перезарядка (тест: 30 с) | кнопка «лупа», перезарядка (тест: 120 с) |
| Обратная связь при ошибке | показывает, что именно неверно (позиция, деталь) | «неверно» + частично (сколько верно) | только «неверно» |
| Цена ошибки | откат на 1 шаг | сброс текущей попытки | сброс текущей попытки |
| Автозапись в блокнот | улики, документы, **коды и числа**, пометки «важно» | улики, документы; коды — по тапу игрока | улики, документы (без выделения ключевого) |
| Подсказки (раздел 4) | 3 ступени, без ожидания, решение показывается на 3-й | 3 ступени, перезарядка (тест: 60 с), 3-я — решение показывается | 3 ступени, перезарядка (тест: 180 с), 3-я — метод + первый шаг, без полного решения |
| Пропуск головоломки | после 3-й подсказки (кроме ключевых для сюжета: там решение показывается пошагово) | после 3-й подсказки | нет |
| Дальние связи | блокнот указывает, где источник | подсказка 1 указывает главу/локацию | только тематическая подсказка |
| Таймеры | нет | нет | нет (допустим необязательный таймер для достижений) |

Все числовые значения в столбцах — **тестовые**, задаются параметрами (`difficulty_profile.*`).

### 3.3. Правила масштабирования для конкретной головоломки
1. Сначала проектируется версия **Н**. Л и С строятся от неё.
2. Л упрощает минимум по двум осям из: элементы, шаги, источники, явность. С усложняет минимум по двум осям.
3. Если на разных уровнях различаются значения (код из 3 знаков на Л и из 4 на Н), источник подсказки тоже параметризован: текст-шаблон и вариант графики на каждый уровень.
4. Ожидаемое время: Л ≈ 0,5–0,7 × Н, С ≈ 1,5–2 × Н.
5. Если С требует дополнительный источник (2-я часть кода), этот источник **должен** находиться в уже открытой на этот момент локации и быть осматриваемым объектом на всех уровнях (на Л/Н он содержит «фоновый» текст), чтобы граф прогрессии не менялся.
6. Головоломки с сюжетно-критичной информацией (ответ нужен для понимания истории) на С не должны быть «непроходимыми»: 3-я подсказка даёт метод, а решение доступно через пропуск после повторного запроса и подтверждения (параметр `hard_allow_reveal`, по умолчанию выключен; включается только для таких головоломок).

Конкретное масштабирование по типам дано в разделе 2 (строки «Л / Н / С»).

## 4. Система подсказок

### 4.1. Состав
1. **Блокнот детектива** (доступен всегда, кнопка в углу экрана). Разделы:
   - **Улики** — предметы и факты (автоматически, все уровни);
   - **Документы** — копии всех прочитанных записок, писем, книжных страниц (автоматически, все уровни). Можно открыть в любой момент, не возвращаясь в локацию;
   - **Снимки** — «фото» любого крупного плана (кнопка-камера на экране осмотра). Решает проблему «записать» на телефоне. Все уровни;
   - **Коды и числа** — Л: автоматически; Н: игрок тапом выделяет фрагмент документа/картинки → запись; С: так же, как Н, но без выделения ключевых фрагментов цветом;
   - **Открытые вопросы** — незакрытые головоломки и замеченные, но не использованные наблюдения (запертые двери, непонятные символы). Л и Н: автоматически; С: только запертые объекты;
   - **Заметки игрока** — свободный текст и стикеры на снимках, все уровни;
   - **Журнал подсказок** — все полученные подсказки по каждой головоломке (перечитать бесплатно, без перезарядки), все уровни;
   - **Метазагадка** (T22) — после первого фрагмента.
2. **Лупа** — подсветка активных зон текущего экрана (параметры уровней — таблица 3.2).
3. **Реплики героя** — при осмотре и при неверном действии герой говорит осмысленную фразу, наводящую на мысль (на всех уровнях одинаково — это часть мира, не система подсказок).
4. **Многоступенчатая подсказка** (кнопка «?» на экране головоломки и на экране локации).

### 4.2. Ступени подсказки
Подсказка привязана к текущему **шагу** прогрессии, а не просто к головоломке: если игрок ещё не нашёл нужный предмет, подсказка ведёт к предмету, а не к решению замка.

| Ступень | Назначение | Пример формулировки |
|---|---|---|
| 1. Направление | что важно / где искать | «Владелец сейфа не доверял памяти. Где он мог записать важное?» |
| 2. Метод | как связать найденное | «Числа в записке стоят не по порядку — сравни их с номерами на полках.» |
| 3. Решение | Л/Н — ответ или пошаговая демонстрация; С — метод полностью + первый шаг | «Первое число — с полки с синим корешком: 4.» |

Правила:
- Каждая ступень не раскрывает больше, чем нужно для следующего шага мысли.
- Подсказки — тексты-шаблоны с параметрами (`{code}`, `{location_name}`), чтобы не расходиться с тестовыми/релизными значениями.
- Перезарядка считается от момента открытия предыдущей ступени и только пока головоломка/локация активна (не тикает в свёрнутом приложении).
- Подсказка «где искать» на Н/С не называет предмет прямо, только место или область.
- Если игрок три раза подряд ошибся в одной головоломке, кнопка «?» мягко пульсирует (все уровни; на С — после 5 ошибок).
- Монетизация подсказок в этом документе не рассматривается. **Открытый вопрос для владельца/маркетолога:** подсказки бесплатны с перезарядкой (базовое предложение) или частично платные.

## 5. Двуязычность (RU / EN)

### 5.1. Классы
- **A — безопасно.** Решение не опирается на текст: числа, символы мира, цвета (с символами), позиции, формы, механика. Переводятся только интерфейс и реплики.
- **B — текст несёт информацию, ответ нелингвистический.** Текст пишется отдельно для RU и EN (не дословный перевод, а эквивалент с тем же фактом), ответ одинаковый. Обязательна проверка эквивалентности.
- **C — текст в графике.** Надписи на картинах, вывесках, обрывках, картах. Нужна **локализованная версия ассета**; в карточке перечисляются все такие ассеты.
- **D — запрещено.** Решение зависит от свойств языка.

### 5.2. Запрещено (D)
- акростихи, первые/последние буквы слов;
- число букв в слове, длина слова как ответ;
- алфавитный порядок и сортировка по названию;
- анаграммы, палиндромы, рифмы, каламбуры, игра слов, омонимы;
- ответ-слово, которое игрок вводит с клавиатуры;
- буквенные координаты (A1, Б2) и буквенные коды;
- грамматический род как подсказка (раскрывает пол, есть в RU, нет в EN);
- форматы, читаемые по-разному: даты ДД.ММ / ММ/ДД, 12/24-часовое время, десятичная запятая/точка, единицы (фунты/кг, мили/км).

### 5.3. Разрешённые приёмы для «текстовых» головоломок
- числа словами допустимы («в седьмой раз» / «for the seventh time») — смысл одинаков;
- ответ — выбор из карточек/изображений, а не ввод текста;
- вымышленный алфавит/символы мира с таблицей соответствий **символ → число/пиктограмма**;
- если шифр буквенный — отдельный ключ и шифротекст для каждого языка (схема B для T02);
- позиционные указания («третья строка, пятое слово» — **запрещено**; «третья строка, число в ней» — разрешено);
- имена персонажей и названия мест в мире — одинаковые для обоих языков, транслитерация фиксируется в глоссарии сценариста.

### 5.4. Как оформлять в карточке

```
### RU / EN
- Класс перевода: B
- Как работает на RU: в письме сказано «…приду ровно через {hours} часа после боя часов…»; игрок считает время по часам в холле.
- Как работает на EN: «…I'll come exactly {hours} hours after the clock strikes…»; то же вычисление.
- Ответ одинаков: да — {target_time}.
- Сложность одинакова: длина текста RU 46 слов / EN 41 слово; ключевой факт в той же позиции (2-е предложение).
- Локализуемая графика: нет / список ассетов (например, `img_sign_pharmacy_ru.png`, `img_sign_pharmacy_en.png`).
- Пометки для переводчика: «{hours} — параметр, не заменять словом; фразу о бое часов сохранить в одном предложении».
```

Требования к верстке: EN-тексты обычно короче, RU длиннее на 10–30 % — окна документов рассчитываются на RU; шрифты «рукописных» записок должны поддерживать кириллицу и латиницу в едином стиле.

## 6. Дальние связи

### 6.1. Определение
Дальняя связь (`LL-xx`) — подсказка, найденная в главе 1–2, которая применяется в главе 5–6. Цель на игру: **4–6 дальних связей**, из них 1–2 участвуют в метазагадке.

### 6.2. Правила честности
1. **Источник заметен как объект, но не как «головоломка».** Это отдельный осматриваемый предмет с крупным планом (картина, гравюра, записка), а не деталь фона. При первом осмотре герой реагирует фразой, которая делает деталь запоминающейся, но не объясняет её назначение.
2. **Источник не исчезает.** Либо локация остаётся доступной до конца игры, либо источник автоматически хранится в блокноте (Документы / Снимки) с полным качеством, достаточным для решения. Предпочтительно и то и другое: бриф требует, чтобы игрок мог «вернуться и заметить».
3. **Эхо в середине.** Между источником и применением — минимум одно напоминание (глава 3–4): тот же символ на другом предмете, упоминание в письме, реплика персонажа. Игрок не должен держать в голове деталь 3–5 часов без повода.
4. **Узнавание в приёмнике.** В месте применения есть явная визуальная или смысловая отсылка к источнику (тот же орнамент, тот же символ, та же фраза).
5. **Нет ложного «замка» в начале.** Если источник выглядит как загадка, но решить её в начале нельзя, блокнот помечает её в «Открытых вопросах» как наблюдение («Странный узор на раме. Пока не понятно, к чему он»), чтобы игрок не тратил время.
6. **Нет преждевременного решения.** Приёмник не появляется раньше, чем запланировано, а значение источника не должно решать другие головоломки по ошибке (уникальные символы/числа).
7. **Параметризация.** Значение в источнике — параметр приёмника; меняется в одном месте.

### 6.3. Помощь по уровням
| | Лёгкий | Нормальный | Сложный |
|---|---|---|---|
| При первом осмотре источника | запись в «Открытых вопросах» с пометкой «может пригодиться» | запись в «Открытых вопросах» | только копия в Документах/Снимках |
| При встрече приёмника | блокнот: «Это похоже на то, что ты видел в {location}, глава {n}» + кнопка «открыть запись» | ничего автоматически | ничего |
| Подсказка 1 | указывает конкретную запись | указывает главу и локацию | «Ты уже видел этот символ раньше» |
| Подсказка 2 | что именно в записи важно | какая запись | глава |
| Подсказка 3 | решение | решение | метод и первый шаг |

### 6.4. Оформление
Каждая дальняя связь описывается в реестре `docs/levels/long-links.md` (создаётся вместе с первыми карточками):
`LL-ID | источник (PZ/объект, глава, локация) | эхо (где) | приёмник (PZ, глава) | что переносится | хранится ли в блокноте | доступна ли локация повторно`.
В карточке головоломки-приёмника поле «Дальняя связь» обязательно. Плейтест: каждая дальняя связь проверяется отдельно тестировщиком, который не знает о ней заранее.

Релизные значения не должны совпадать с тестовыми ни в одной головоломке.

## 8. Кривая сложности и распределение

### 8.1. Темп и сессии (мобильный формат)
- Целевая сессия: 10–20 минут. Глава делится на **эпизоды** по 3–6 головоломок (~15–25 мин на Н); конец эпизода — естественная точка выхода (сюжетная сцена, автосохранение).
- Автосохранение: после каждой решённой головоломки, после каждого этапа многоэтапной, при входе в локацию, при сворачивании.
- При возвращении после паузы — экран «Ранее в деле» (2–3 строки из блокнота: текущая цель, последние улики).
- Чередование внутри эпизода: поиск/осмотр → головоломка → документ/диалог → головоломка → итог (доска дедукции или сюжетная сцена). Не ставить подряд два однотипных (T08 и T05 особенно).
- После самой сложной головоломки эпизода — 1–2 лёгких («передышка»).
- Новый тип впервые появляется с рейтингом ≤ 2 и с короткой обучающей репликой/подсказкой интерфейса.

### 8.2. Главы
| Глава | Головоломок | Рейтинг (Н) | Время на головоломку (Н) | Особенности |
|---|---|---|---|---|
| 1. Завязка / обучение | 12 | 1–2 | 1–3 мин | знакомство с 8–10 типами; источники 2–3 дальних связей; без сложных многоэтапных |
| 2. Первые зацепки | 16 | 1–3 | 2–4 мин | остальные базовые типы; первая доска дедукции; ещё 1–2 источника дальних связей |
| 3. Расширение | 18 | 2–4 | 3–6 мин | первая многоэтапная (T21 или 2–3-этапная), эхо дальних связей, логические сетки |
| 4. Поворот | 20 | 2–4 | 3–7 мин | смешанные типы, возвраты в старые локации (новые объекты в них), 1–2 приёмника дальних связей |
| 5. Развязка близко | 20 | 3–5 | 4–10 мин | сложные комбинации типов, большая часть приёмников дальних связей |
| 6. Финал | 14 | 3–5 | 4–12 мин | метазагадка, последние приёмники, финальная доска дедукции, затем 1–2 лёгкие головоломки перед роликом |

## 9. Чек-лист проверки головоломки перед тестом
- [ ] Все поля карточки заполнены, значения — параметры, тексты — шаблоны.
- [ ] Решение выводимо из того, что игрок мог увидеть до этого момента (проверено по графу прогрессии).
- [ ] Нет тупика: нужные предметы нельзя потерять/использовать не туда безвозвратно.
- [ ] Ограничения значений проверены (единственность решения, решаемость, нет совпадений с другими кодами).
- [ ] Л и С отличаются от Н минимум по двум осям; граф прогрессии на всех уровнях одинаков.
- [ ] Класс перевода указан; нет приёмов из списка D; RU и EN описаны, локализуемые ассеты перечислены.
- [ ] Зоны касания ≥ 48 dp, решение без щипка, цвет дублирован символом, звук — визуалом.
- [ ] Время на Н соответствует главе; если > 5 мин — есть этапы с сохранением.
- [ ] Подсказки 1–2–3 заполнены и ведут к текущему шагу.
- [ ] Для дальних связей: источник хранится в блокноте, есть эхо, приёмник отсылает к источнику.
- [ ] Механика не повторяет узнаваемую головоломку из существующей игры.

## 10. Открытые вопросы
1. Формат данных (YAML/JSON, структура файлов) — согласовать с программистом, когда он подключится.
2. Ориентация экрана (предлагается горизонтальная) — согласовать с дизайнером (`docs/design/`).
3. Подсказки бесплатны с перезарядкой или частично платные — решение владельца/маркетолога.
4. Где хранить релизные значения (в репозитории в отдельной папке или вне его) — решение владельца.
5. Можно ли менять уровень сложности посреди игры (предложение: да, в меню; влияет на ещё не начатые головоломки, начатые сохраняют параметры до решения).
