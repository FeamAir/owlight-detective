# Каркас головоломок (puzzle framework)

Статус: черновик v2.1, левел-дизайн. Переработан под «Решения владельца (26.11.2026)» из `docs/00-brief.md`: одна карта без глав, панорама 360°, сложность фиксируется при старте, подсказки только навигационные голосом героини, стопроцентная логика.
v2.1: героиня — Клара Вест (решение №10), примеры реплик в женском роде; подсказки на нормальном уровне — «по запросу с ожиданием» (решение №13, раздел 3.5); озвучки в разработке нет, только субтитры (решение №11); столбец «Ворота входа» в 8.1 сверен с `docs/story/story-bible.md` 7.2. Полный список головоломок — `docs/levels/puzzle-list.md`.

Документ описывает правила, типы, шаблоны и распределение. Конкретные головоломки описываются по шаблону из раздела 10 в файлах зон `docs/levels/act-<N>-<зона>.md`.

Требования, на которые опирается документ:
- около 100 головоломок (план — 104, согласован с `docs/story/story-bible.md`), разные типы и сложность, есть многоэтапные;
- несколько дальних связей: подсказка в начале игры, применение ближе к концу;
- одна сплошная карта усадьбы, свободное перемещение. Прогресс ограничен только дверями, тайниками и проходами, которые открываются разгадками и предметами. Внутренние акты нужны для темпа, игрок их не видит;
- вид от первого лица, горизонтальный экран, панорамы 360°: свайп поворачивает голову, тап по направлению делает шаг, тап по объекту открывает крупный план;
- три уровня сложности. Уровень выбирается при старте и в игре не меняется. Сюжет, карта и граф прогрессии на всех уровнях одинаковы;
- подсказки бесплатные и без рекламы. Они только навигационные («куда идти и что сделать дальше») и звучат внутренним голосом героини. Решений не дают, пропуска головоломок нет;
- стопроцентная логика: решение выводится из найденного в игре, после ответа игрок понимает, почему он такой;
- RU и EN: та же логика, та же сложность, тот же ответ;
- у каждой головоломки разделены механика, тестовые значения и релизные значения, значения хранятся как параметры;
- мобильный формат (Android): сенсорный экран, короткие сессии;
- всё оригинальное.

Условные обозначения:
- **Л / Н / С** — лёгкий / нормальный / сложный.
- **Акт** — внутренний блок темпа (раздел 8). Игрок его не видит, в интерфейсе актов нет.
- **ID:** головоломка `PZ-<LOC>-<nn>` (пример: `PZ-HALL-02`; номер не зависит от порядка прохождения), локация `LOC-...`, точка обзора `VP-<LOC>-<n>`, активный объект `HS-...`, ворота `GT-...`, предмет `IT-...`, улика или подсказка `CL-...`, дальняя связь `LL-..`.
- **Рейтинг сложности:** 1–5, оценивается для уровня Н. На Л ощущается примерно на 1 ниже, на С на 1 выше.
- **Класс перевода:** A / B / C / D (раздел 5).

## 1. Общие принципы

1. **Стопроцентная логика.** Всё, что нужно для решения, игрок может найти в игре до момента решения. Решение единственное, угадывать ничего не нужно. После ответа игра коротко показывает логику. Подробности и проверка — в разделе 4.
2. **Одна головоломка — одна главная идея.** Многоэтапные головоломки собираются из этапов. У каждого этапа своя идея и своя точка сохранения.
3. **Подсказка и замок разнесены.** Источник подсказки и место применения обычно находятся в разных объектах или локациях. Исключение — обучающие головоломки стартовой зоны.
4. **Значения — параметры.** Ни одно число, символ или комбинация не пишется в тексты и графику «намертво». Тексты делаются шаблонами (`{code}`), графика с числами — слоями или вариантами.
5. **Без наказания временем и без тупиков.** Нет таймеров с проигрышем и блокировки замка после ошибок. Ключевые предметы нельзя потерять или истратить не туда. Ни одна локация с источником подсказки не закрывается навсегда (раздел 7).
6. **Без пиксель-хантинга.** Активная зона не меньше 48 dp с каждой стороны при стандартном поле зрения панорамы. Активные объекты читаются художественно и без подсветки, потому что на С подсветки нет (раздел 6).
7. **Прерываемость.** Состояние сохраняется при сворачивании. Головоломки дольше 5 минут на Н делятся на этапы с автосохранением.
8. **Доступность.** Цвет всегда дублируется формой или символом, звук — визуальным каналом.
9. **Оригинальность.** Классические математические основы допустимы, но не в узнаваемом «каноническом» виде из других игр: своя рамка, свой предмет, свои правила.

## 2. Таксономия типов (22 типа)

Для каждого типа указаны суть, управление на сенсорном экране, параметры, ограничения на значения, масштабирование на Л/Н/С, класс перевода и риски. Во всех строках «Л / Н / С» помощь на Л — это обратная связь «где ошибка» и удобства интерфейса. Показа решения нет ни на одном уровне (раздел 3).

Базовые жесты на экране крупного плана или головоломки (навигация по панораме — раздел 6):
- **тап** — осмотр, выбор, нажатие;
- **перетаскивание** — перемещение детали или предмета из инвентаря, с «магнитом» к допустимым позициям;
- **круговой свайп** — вращение диска, кольца, ручки с привязкой к шагам;
- **щипок** — приближение, только для осмотра: решение не должно требовать щипка;
- **долгое нажатие** — подробное описание, добавление в блокнот.

### T01. Кодовый замок
- **Суть:** ввести код (цифры, символы, положения дисков), выведенный из найденных подсказок.
- **Управление:** тап по кнопкам или вертикальный свайп по барабанам; кнопка «открыть».
- **Параметры:** `code`, `code_length`, `alphabet` (цифры / знаки мастерской / цвета), `input_kind`, `code_parts[]` (часть кода и её источник).
- **Ограничения значений:** код не очевиден (не 0000, не 1234); каждая часть кода берётся ровно из одного источника, порядок частей задан в подсказке (номера, стрелки, позиции).
- **Л / Н / С:** Л — 3 знака, один источник, код записывается в блокнот автоматически, при ошибке указывается неверная **часть** кода и её источник; Н — 4 знака, 1–2 источника, при ошибке сообщается, сколько частей верны; С — 4–5 знаков, 2–3 источника, части нужно вывести (посчитать, сопоставить), в окружении есть похожие ложные числа, при ошибке только «неверно».
- **Перевод:** A (число или символ на предмете) или B (код выводится из текста).
- **Риски:** перебор вместо решения. Обратная связь указывает на часть кода, а не на отдельный знак. Пространство вариантов не меньше 6³, анимация проверки 0,5–1 с.

### T02. Символьный шифр (знаки мира)
- **Суть:** расшифровать сообщение по ключу. Ключ найден отдельно или собирается по частям.
- **Управление:** тап по символу сообщения, затем выбор значения из ключа. Ответ выбирается из вариантов, с клавиатуры не вводится.
- **Параметры:** `key_map`, `message`, `key_fragments[]`, `answer`, `answer_kind` (число / предмет / место).
- **Ограничения значений:** ключ однозначно декодирует сообщение; ответ нелингвистический.
- **Л / Н / С:** Л — ключ целиком, короткое сообщение, автоподстановка одинаковых символов; Н — ключ из 2 частей, до 20 % символов выводится из контекста; С — ключ из 3 частей, 30–40 % выводится из контекста, без автоподстановки.
- **Перевод:** предпочтительно A (символ → число или пиктограмма). Буквенный шифр — только по схеме B: отдельный ключ и шифротекст для каждого языка, одинаковые длина и доля выводимых символов (±15 %), одинаковый ответ.
- **Риски:** частотный анализ по-разному работает на RU и EN, поэтому тестировать оба языка; на экране не больше 3–4 строк.

### T03. Трафарет / наложение
- **Суть:** наложить один предмет на другой (решётку на таблицу, плёнку на карту, чертёж на чертёж), чтобы проявилась информация.
- **Управление:** перетащить трафарет, повернуть кнопкой «90°» или круговым свайпом, привязка к сетке.
- **Параметры:** `grid_size`, `holes[]`, `base_content`, `rotations_needed`, `result`.
- **Ограничения значений:** осмысленный результат даёт только одно положение.
- **Л / Н / С:** Л — одно положение без вращения, трафарет защёлкивается; Н — нужно найти верный поворот из 4; С — 2 слоя или поворот со сдвигом, на основе есть правдоподобные ложные совпадения.
- **Перевод:** A, если проявляются цифры, символы или точки. Прорези, открывающие буквы, запрещены (D).
- **Риски:** сетка не больше 6×6.

### T04. Механизм
- **Суть:** привести механизм в рабочее состояние: поставить недостающие детали, выставить рычаги, добиться передачи движения.
- **Управление:** перетаскивание деталей на оси, тап по рычагу, кнопка «запустить».
- **Параметры:** `slots[]`, `parts[]` (включая лишние), `target_state`, `lever_links`.
- **Ограничения значений:** решение проверено решателем; нет «почти работающих» состояний, визуально неотличимых от решения.
- **Л / Н / С:** Л — 2–3 детали без лишних, при запуске показывается, на какой оси передача обрывается; Н — 3–5 деталей, 1–2 лишних, запуск показывает только «крутится / не крутится»; С — 5–7 деталей, 2–3 лишних, связанные рычаги, схема (чертёж) лежит в другой локации.
- **Перевод:** A.
- **Риски:** правила механизма должны быть видимы: зубцы, стрелки на рычагах, чертёж. Физика «на глаз» нечестна.

### T05. Слайдер / вращение
- **Суть:** повернуть кольца или переставить плитки, чтобы собрать картинку, символ или выравнивание.
- **Управление:** свайп по ряду или кольцу; кнопка «сброс» всегда доступна.
- **Параметры:** `grid` или `rings_count`, `steps_per_ring`, `linked_rings`, `scramble_seed`, `max_scramble_depth`.
- **Ограничения значений:** состояние решаемо (для перестановок проверять чётность); перемешивание задаётся числом ходов от решения.
- **Л / Н / С:** Л — 3 кольца или 3×3, 6–8 ходов, верно стоящие элементы отмечаются; Н — 4 кольца или 3×3, 12–15 ходов, без отметки; С — 4–5 колец со связанными вращениями или 4×4, 20+ ходов, целевая картинка известна только из другой локации.
- **Перевод:** A.
- **Риски:** механический перебор; «пятнашки» узнаваемы, поэтому тип оформляется как предмет мира. Не больше 6 на игру.

### T06. Комбинирование предметов
- **Суть:** соединить предметы или применить предмет к объекту мира.
- **Управление:** перетащить предмет из инвентаря на объект сцены или на другой предмет.
- **Параметры:** `recipe[]`, `target_hotspot`, `decoys[]`, `wrong_lines` (реплики героини на неверные пары).
- **Ограничения значений:** у каждой комбинации есть логичное объяснение в мире. Неверная комбинация ничего не расходует и не меняет (раздел 7.4).
- **Л / Н / С:** Л — 2 предмета, реплика на неверную пару объясняет, почему не подходит («Слишком толстый для этой щели»); Н — 2–3 предмета, реплика короче; С — 3–4 предмета, промежуточный результат нужно применить ещё раз, реплика нейтральная («Не то»). Состав предметов на всех уровнях одинаков. Подсветки «нужного» предмета в инвентаре нет ни на одном уровне: это было бы решением.
- **Перевод:** A.
- **Риски:** «лунная логика». Каждое сочетание подсказано хотя бы одним из трёх способов: реплика при осмотре, изображение или описание в документе, форма предмета. В инвентаре одновременно не больше 8–10 предметов.

### T07. Сборка из частей
- **Суть:** собрать целое из фрагментов: письмо, фото, табличку, шкатулку.
- **Управление:** перетаскивание, поворот тапом на 90°, магнит к правильным соседям.
- **Параметры:** `pieces_count`, `rotation_enabled`, `missing_pieces[]`, `decoy_pieces`, `edge_hints`.
- **Ограничения значений:** у каждого фрагмента одно место.
- **Л / Н / С:** Л — 4–6 частей без поворота, все на месте, правильные стыки защёлкиваются; Н — 6–9 частей с поворотом, 1–2 части лежат в других локациях; С — 9–12 частей, 2–3 части в других локациях, 1–2 лишних фрагмента от другого предмета.
- **Перевод:** собранный текст — класс C (локализованная графика, разрезы не по границам слов), иначе A.
- **Риски:** мелкие части; больше 12 частей становятся рутиной.

### T08. Поиск в сцене / наблюдательность
- **Суть:** найти в сцене предметы по списку (силуэты, описания) или то, что «не так».
- **Управление:** тап по предмету.
- **Параметры:** `targets[]`, `list_kind`, `clutter_level`.
- **Ограничения значений:** каждый предмет отличим от фона при нормальной яркости; зона касания не меньше 48 dp.
- **Л / Н / С:** Л — 4–5 предметов, список силуэтами, счётчик найденного; Н — 6–7 предметов, силуэты; С — 8 предметов, часть списка дана функцией («чем можно вскрыть конверт»), больше мусора. **Цели поиска не подсвечиваются ни на одном уровне**: подсветка активных зон на них не распространяется, потому что сами цели и есть решение.
- **Перевод:** A для силуэтов, B для описаний.
- **Риски:** утомляемость. Не больше 6 сцен на игру и не больше одной такой сцены среди одновременно открытых задач.

### T09. Сравнение изображений
- **Суть:** найти значимые различия между двумя изображениями (фото до и после, копия и оригинал).
- **Управление:** изображения рядом или переключатель по тапу; отметка различия тапом.
- **Параметры:** `differences[]`, `meaningful_differences[]`, `diff_size`.
- **Л / Н / С:** Л — 3–4 крупных различия, счётчик «осталось N»; Н — 5 различий, счётчик; С — 5–6 различий, часть мелкие (зона касания всё равно не меньше 48 dp), без счётчика, отметить нужно только значимые.
- **Перевод:** A без текста на изображениях, иначе C.
- **Риски:** проверять на экране 5,5''.

### T10. Логическая сетка
- **Суть:** по набору утверждений из записок и показаний определить соответствия (кто, где, когда).
- **Управление:** таблица в блокноте, тап по клетке переключает «нет / да / пусто»; ответ — выбор карточек.
- **Параметры:** `dimensions`, `facts[]`, `solution`, `facts_sources[]`.
- **Ограничения значений:** решение единственно и выводится без угадывания, проверено решателем. На С нет лишних фактов.
- **Л / Н / С:** на всех уровнях при отметке «да» строка и столбец вычёркиваются автоматически (это учёт, а не дедукция). Л — 3×3, избыточные факты, при ошибке указывается неверная строка; Н — 4×4, минимум фактов плюс 1 избыточный, при ошибке сообщается число верных строк; С — 4×4×4, факты разбросаны по 3+ локациям, один факт косвенный, при ошибке только «неверно».
- **Перевод:** B. Утверждения пишутся отдельно для RU и EN с той же логической формой. Грамматический род как подсказка запрещён.
- **Риски:** каждый факт в одну строку, не больше 8 фактов на экране.

### T11. Последовательность и порядок действий
- **Суть:** выполнить действия в правильном порядке по найденной инструкции или закономерности.
- **Управление:** тапы по элементам; ошибка сбрасывает последовательность с явной анимацией.
- **Параметры:** `sequence[]`, `elements_count`, `source`.
- **Л / Н / С:** Л — 3–4 шага, прямая инструкция; ввод проверяется после последнего шага, и героиня говорит, с какого шага порядок разошёлся с источником; Н — 5–6 шагов, порядок нужно сопоставить (например, по датам в документе), сообщается только «сбилось»; С — 6–8 шагов из 2 источников или по закономерности, только «неверно».
- **Перевод:** A, если порядок задан числами, символами, позициями; B, если выводится из текста. Порядок по алфавиту и по первым буквам запрещён.
- **Риски:** перебор на коротких последовательностях, поэтому шаг не подтверждается до конца ввода.

### T12. Звук / музыка
- **Суть:** воспроизвести мелодию или комбинацию звуков, найденную в мире.
- **Управление:** тап по клавишам или колокольчикам.
- **Параметры:** `notes[]` (индексы элементов), `length`, `visual_notation` (обязательна).
- **Ограничения значений:** у каждого звука есть визуальная пара (цвет + форма или номер). Решается без звука.
- **Л / Н / С:** Л — 4 звука, клавиши пронумерованы так же, как запись, мелодия записывается в блокнот автоматически; Н — 5–6 звуков, запись знаками мира, соответствие клавиш нужно найти; С — 7–8 звуков, запись неполная, недостающее берётся в другом источнике.
- **Перевод:** A.
- **Риски:** высоту звука на слух не требовать.

### T13. Свет / тени / цвет
- **Суть:** направить луч зеркалами, смешать фильтры, поставить предмет так, чтобы тень дала знак, проявить скрытые чернила.
- **Управление:** тап по зеркалу (поворот на шаг), перетаскивание фильтра, круговой свайп по источнику.
- **Параметры:** `grid`, `mirrors_count`, `filters[]`, `target`, `color_rules`.
- **Ограничения значений:** у каждого цвета есть символ или узор; правила смешения показаны в мире.
- **Л / Н / С:** Л — 2–3 зеркала, луч виден постоянно; Н — 4–5 зеркал, 1 фильтр; С — 5–6 зеркал, 2 фильтра, цель определяется по подсказке, видимой только при определённом освещении.
- **Перевод:** A.
- **Риски:** дальтонизм; яркость экрана на улице.

### T14. Карта и ориентация
- **Суть:** найти точку на плане по описанию маршрута, ориентирам, сторонам света.
- **Управление:** карта на весь экран, тап ставит метку, круговой свайп вращает.
- **Параметры:** `map_asset`, `target_point`, `route_steps[]`, `landmarks[]`, `grid_labels`.
- **Ограничения значений:** координаты обозначаются цифрами или знаками мира, не буквами; роза ветров — символами.
- **Л / Н / С:** Л — 2–3 шага маршрута, сетка подписана, при неверной метке героиня называет шаг маршрута, после которого путь ушёл в сторону; Н — 4–5 шагов, карту нужно сориентировать по ориентиру; С — 5–7 шагов, часть маршрута в другом документе, карта без сетки.
- **Перевод:** подписи на карте — C или знаки мира; маршрут в тексте — B. Буквенные координаты запрещены.
- **Риски:** мелкая карта на телефоне, поэтому она делится на фрагменты.

### T15. Анализ документов
- **Суть:** сопоставить письма, расписания, счета, дневник и найти противоречие, факт или число.
- **Управление:** документы в блокноте, режим «сравнить» (два рядом), тап выделяет фрагмент; ответ — выбор фрагментов-доказательств или число.
- **Параметры:** `documents[]`, `key_fragments[]`, `answer`, `answer_kind`.
- **Ограничения значений:** ответ не зависит от формулировки; даты только в однозначном формате; время — 24 часа или аналоговые часы.
- **Л / Н / С:** Л — 2 документа, ключевые фрагменты выделены в блокноте, при неверном выборе сказано, какой из выбранных фрагментов не доказывает вывод; Н — 2–3 документа без выделения; С — 3–4 документа плюс 1–2 с правдоподобными ложными данными.
- **Перевод:** B. Ключевые фрагменты пишутся для каждого языка с тем же фактом.
- **Риски:** документ не длиннее ~120 слов на RU; ключ не в последней строке.

### T16. Анализ изображений
- **Суть:** найти на картине, фото или гравюре деталь, несущую информацию.
- **Управление:** изображение на весь экран, щипок, тап по детали добавляет её в блокнот.
- **Параметры:** `image_asset`, `key_details[]`, `derived_value`, `variants`.
- **Ограничения значений:** ключевая деталь видна на экране 5,5'' без максимального увеличения.
- **Л / Н / С:** Л — 1 деталь, крупная и контрастная (решается художественно, а не указателем), изображение целиком сохраняется в «Снимки»; Н — 1–2 детали; С — 2–3 детали, которые нужно сопоставить.
- **Перевод:** A без надписей, C с надписями.
- **Риски:** художнику нужно точное ТЗ, что и где изображено; значение детали — параметр.

### T17. Соединения
- **Суть:** соединить точки так, чтобы ток или вода дошли до цели.
- **Управление:** тап по сегменту (поворот) или проведение пальцем.
- **Параметры:** `grid_size`, `tiles[]`, `sources[]`, `sinks[]`, `blocked_cells[]`.
- **Ограничения значений:** решение единственно или засчитываются все решения; проверено решателем.
- **Л / Н / С:** Л — 4×4, 1 источник, подключённые сегменты светятся; Н — 5×5, 2 источника; С — 6×6, 2–3 источника, запрет пересечений, часть плиток закреплена.
- **Перевод:** A.
- **Риски:** больше 6×6 неудобно.

### T18. Весы / измерения
- **Суть:** уравновесить весы, отмерить объём, подобрать грузы по записи.
- **Управление:** перетаскивание грузов; переливание тапом «источник → цель».
- **Параметры:** `weights[]`, `target`, `vessels[]`, `capacities[]`.
- **Ограничения значений:** решение существует, минимальное число шагов известно.
- **Л / Н / С:** Л — 3–4 груза, шкала показывает разницу числом; Н — 4–5 грузов, шкала «легче / тяжелее»; С — 5–6 грузов, вес одного груза выводится из документа.
- **Перевод:** A. Единицы условные (насечки, гири с точками).
- **Риски:** классические переливания узнаваемы.

### T19. Часы и время
- **Суть:** выставить время на часах, календаре, солнечных часах по найденному событию или расчёту.
- **Управление:** круговой свайп по стрелкам с привязкой; календарь — барабаны.
- **Параметры:** `target_time`, `snap_minutes`, `source`, `offset_rule`.
- **Ограничения значений:** аналоговые часы или 24 часа, без AM/PM.
- **Л / Н / С:** Л — время дано прямо, привязка 15 мин; Н — время вычисляется из одного документа, привязка 5 мин; С — из 2 источников, привязка 1 мин.
- **Перевод:** A / B.
- **Риски:** формат времени в EN, поэтому опираться на часы на картинке.

### T20. Доска дедукции
- **Суть:** связать улики в утверждения и сделать вывод (кто, как, почему).
- **Управление:** доска в блокноте, карточки улик перетаскиваются в слоты («[улика] доказывает, что [вывод]»), вывод выбирается из вариантов.
- **Параметры:** `slots[]`, `cards_pool[]`, `correct_links[]`, `conclusion_options[]`.
- **Ограничения значений:** каждая связь обоснована текстом улики.
- **Л / Н / С:** Л — 3 слота, нужные карточки + 1 лишняя, при ошибке отмечаются неверные слоты; Н — 4–5 слотов, 2–3 лишние карточки, сообщается число верных слотов; С — 5–6 слотов, в пуле все карточки акта, только «неверно».
- **Перевод:** B.
- **Риски:** карточка не длиннее 8 слов.

### T21. Шкатулка / многоэтапный объект
- **Суть:** один предмет с несколькими секретами. Каждый этап — свой мини-тип (T01, T04, T05, T11...).
- **Управление:** предмет поворачивается на 4 стороны свайпом; этапы раскрываются последовательно.
- **Параметры:** `stages[]`, `stage_checkpoints` (всегда да).
- **Л / Н / С:** Л — 2–3 этапа, после этапа подсвечивается место следующего (это подсветка активной зоны); Н — 3–4 этапа; С — 4–5 этапов, один этап требует предмет или подсказку из дальней зоны (возможна дальняя связь).
- **Перевод:** худший класс среди этапов.
- **Риски:** этап не дольше 4 мин на Н, сохранение после каждого.

### T22. Метазагадка
- **Суть:** ответ собирается из знаков, разбросанных по всей карте. Решается в финале.
- **Управление:** страница блокнота «Метазагадка»: фрагменты добавляются автоматически на всех уровнях, финал — расстановка фрагментов.
- **Параметры:** `fragments[]` (где каждый), `assembly_rule`, `answer`.
- **Ограничения значений:** каждый фрагмент получается на обязательном пути; правило сборки подсказано в финальной локации.
- **Л / Н / С:** Л — фрагменты стоят на местах, нужно понять только правило; Н — фрагменты нужно расставить; С — 1–2 фрагмента нужно прочитать заново в свете финального знания.
- **Перевод:** A.
- **Риски:** игрок не понимает, что собирает метазагадку, поэтому страница появляется после первого фрагмента с пустыми слотами.

## 3. Уровни сложности

### 3.1. Выбор уровня
- Уровень выбирается на экране «Новая игра» и хранится в сохранении (`difficulty: easy | normal | hard`). В игре он не меняется. Сменить уровень можно только новой игрой.
- На экране выбора каждый уровень описан одной строкой, чтобы выбор был осознанным:
  - Лёгкий: «Активные предметы подсвечены, важное записывается само, мысли героини всегда подскажут, куда идти».
  - Нормальный: «Меньше помощи. Застряли — попросите Клару подумать: мысль придёт через несколько минут, а пока можно искать самим».
  - Сложный: «Без подсветки и без подсказок. Только вы и улики».
- На всех уровнях есть строка: «Решения головоломок игра не подсказывает ни на одном уровне».

### 3.2. Что не меняется никогда
- Сюжет, карта, локации, ворота, граф прогрессии (что открывает что).
- Набор обязательных предметов и улик и места, где они лежат.
- Механика головоломки (тип и правила).
- Дальние связи (на Л их легче заметить).
- Показ логики после правильного ответа (раздел 4.3).
- Видимые указатели переходов в панораме (раздел 6.3): навигация — это управление, а не головоломка.

На С можно добавить **отвлекающие** объекты, документы и детали, если они не создают обязательных шагов и не блокируют прогресс.

### 3.3. Что меняется

| Параметр | Лёгкий | Нормальный | Сложный |
|---|---|---|---|
| Число элементов, шагов, источников | минимум | средне | максимум |
| Явность подсказки в мире | прямая («код 482») | требует сопоставления | требует вывода или расчёта |
| Отвлекающие детали | нет | немного, явно второстепенные | есть, правдоподобные |
| Подсветка активных зон в панораме | постоянно, мягкое свечение, стрелки у края экрана к неосмотренным объектам | кнопка «Осмотреться»: подсветка текущей панорамы на 3 с, перезарядка (тест: 30 с) | нет |
| Отметка «осмотрено, ничего нового» | да | да | нет |
| Автозапись в блокнот | улики, документы, **коды, числа, мелодии**; ключевые фрагменты выделены | улики, документы; коды и числа — по тапу игрока | улики, документы без выделения; коды — по тапу |
| «Открытые вопросы» в блокноте | автоматически, с пометкой «может пригодиться» | автоматически | только запертые объекты |
| Обратная связь при ошибке | где ошибка: какая часть ответа неверна и с каким источником она расходится | «неверно» + сколько частей верны или общая реплика героини | только «неверно» |
| Цена ошибки | верные части ответа сохраняются | сброс текущей попытки | сброс текущей попытки |
| Показ логики после решения | да | да | да |
| Навигационные подсказки (раздел 3.5) | кнопка всегда, мысль сразу | кнопка всегда, мысль приходит после ожидания (тест: 5 мин), игрок играет дальше | нет кнопки |
| Дальние связи | у приёмника запись «Похоже на то, что я видела в {location}» со ссылкой на запись | автоматически ничего, может указать навигационная подсказка | ничего |
| Таймеры | нет | нет | нет |

Все числа — **тестовые**, задаются параметрами (`difficulty_profile.*`).

**Граница допустимой помощи.** Помощь может показывать *где* (активные зоны, место ошибки, куда идти) и *что уже известно* (автозаписи). Помощь не может показывать *какой ответ*: код, порядок, нужный предмет, нужную клетку, цель поиска. Отметка ошибки указывает на **логическую часть** ответа (часть кода из одного источника, строка таблицы, слот доски), а не на отдельный знак, если по отдельному знаку можно подобрать ответ перебором.

### 3.4. Масштабирование конкретной головоломки
1. Сначала проектируется версия Н, Л и С строятся от неё.
2. Л упрощает минимум по двум осям из: элементы, шаги, источники, явность. С усложняет минимум по двум осям.
3. Если значения на уровнях разные (3 знака на Л и 4 на Н), источник подсказки тоже параметризован: шаблон текста и вариант графики на каждый уровень.
4. Ожидаемое время: Л ≈ 0,5–0,7 × Н, С ≈ 1,5–2 × Н.
5. Если С требует дополнительный источник, он лежит в уже открытой к этому моменту локации и осматривается на всех уровнях (на Л и Н содержит «фоновый» текст), чтобы граф не менялся.
6. На С нет ни подсказок, ни пропуска, поэтому сюжетно-критичные головоломки защищаются только качеством дизайна: проверка честности (раздел 4) и отдельный плейтест на С. Если тестировщик на С застревает больше 15 мин на одной головоломке и не может объяснить, чего ему не хватает, головоломка переделывается (явность источника, читаемость объекта), а не получает обходной путь.

### 3.5. Навигационные подсказки

**Что это.** Кнопка «Мысли» (иконка героини). По нажатию героиня говорит короткую фразу внутренним голосом: куда идти и что сделать дальше. В разработке — только текст (субтитр), озвучки нет (решение №11); у каждой фразы ID, текст RU/EN и пустое поле аудиофайла, голос подставляется на этапе озвучки. Решений головоломок, ответов, кодов, нужных предметов и порядка действий подсказка не даёт никогда. Пропуска головоломок нет.

**Две ступени точности.**
| Ступень | Что говорит | Пример |
|---|---|---|
| 1. Область | зона или локация и тип дела | «В саду я ещё не всё осмотрела». |
| 2. Точно | локация, объект и цель (без способа) | «Солнечные часы в лабиринте. Надо понять, что за время они показывают». |

Дополнительные виды фраз (всё ещё навигация):
- **Готовность.** Игрок на экране головоломки и у него есть всё нужное: «Для этого замка у меня, похоже, всё есть. Надо ещё раз подумать над записями». Нужного не хватает: «Тут мне чего-то не хватает. Может, в библиотеке что-то найдётся».
- **Дальняя связь.** «Этот знак... Я видела его раньше. Кажется, в холле».
- **Новое в старом месте.** «В гостиной что-то изменилось после того, как пошли часы».

Запрещено в подсказке: число, символ, цвет или порядок из ответа; название предмета, который надо применить (если комбинирование — головоломка); указание на цель в сцене поиска (T08); «как» решать.

**Как система выбирает, куда направить.** Подсказка строится по графу прогрессии (раздел 7.6) и состоянию игрока:
1. **Фронт.** Множество узлов, у которых выполнены все требования и которые ещё не пройдены: решаемые головоломки, объекты с не взятыми обязательными предметами или уликами, непосещённые доступные локации.
2. **Знания.** Каждый источник информации (`CL-...`) ставит флаг «видел», когда игрок его осмотрел. Головоломка из фронта «готова», если у игрока есть все её предметы и флаги знаний. Если не готова, целью становится объект-источник недостающего (он тоже во фронте, иначе граф нарушен).
3. **Приоритет:**
   а) головоломка, которую игрок трогал последней и бросил (продолжение намерения игрока): если готова, фраза готовности, если нет, путь к недостающему источнику;
   б) готовые головоломки на обязательном пути;
   в) источники недостающего для обязательных головоломок;
   г) новые доступные локации;
   д) необязательные головоломки — только если фронт обязательного пуст.
   При равенстве выбирается ближайшая цель по числу переходов между точками обзора. Цель, о которой только что подсказывали, при следующем запросе уходит в конец очереди, чтобы игрок слышал разные варианты.
4. **Фраза.** У каждого узла графа в данных есть ключи `nav.area` и `nav.precise` (шаблоны с `{location}`). Фразы короткие, до 12 слов на RU, звучат как мысль героини, а не как системное сообщение.

**Подсказка по уровням.**
- **Лёгкий.** Кнопка доступна всегда, мысль приходит **сразу**. Первое нажатие — область, второе (по той же цели) — точно. Вместе с точной фразой на карте усадьбы (если она будет, раздел 6.5) отмечается локация, без указания объекта.
- **Нормальный.** Кнопка доступна всегда, мысль приходит **после ожидания** (правило ниже, решение владельца №13).
- **Сложный.** Кнопки нет. Голос героини звучит только как часть мира: реплики при осмотре, при неверном действии, показ логики. Эти реплики одинаковы на всех уровнях и не адаптируются к застреванию.

**Нормальный уровень: «по запросу с ожиданием» (решение владельца №13).**

Ранее рассмотренные варианты («запас», «перезарядка», «по застреванию») сняты решением владельца. Действующее правило:

1. **Запрос.** Кнопка «Мысли» доступна всегда. Игрок сам решает, что застрял, и нажимает её. Нажатие запускает ожидание `hint.normal.wait_minutes` (тест: **5 мин**). Клара отвечает сразу короткой репликой-подтверждением без содержания («Надо подумать. Пока осмотрюсь ещё»), чтобы нажатие не казалось проигнорированным.
2. **Пока идёт ожидание, игра не ограничивается.** Игрок ходит, осматривает, решает головоломки, читает документы. Ничего не блокируется и не замедляется.
3. **Мысль «созревает».** По окончании ожидания кнопка переходит в состояние «мысль готова» (см. п. 8). Окно **не всплывает само** и не прерывает головоломку, документ, диалог или ролик: игрок открывает мысль тапом, когда ему удобно. Готовая мысль не сгорает и хранится до прочтения или отказа.
4. **Пересчёт под актуальную цель.** Содержание мысли выбирается **в момент открытия**, а не в момент нажатия: алгоритм выбора цели (выше, п. 1–4) запускается по текущему состоянию. Если за время ожидания игрок продвинулся (решил головоломку, нашёл предмет, открыл локацию), мысль будет о том, что актуально сейчас, а не о цели, которая была на момент нажатия. Частные случаи:
   - игрок сейчас на экране головоломки, для которой у него всё есть, — фраза готовности («Для этого замка у меня, похоже, всё есть»);
   - цель, о которой была прошлая мысль, ещё не пройдена и игрок к ней не продвинулся — выдаётся вторая ступень («точно»);
   - цель сменилась — снова первая ступень («область») для новой цели;
   - обязательный фронт пуст и остались только необязательные головоломки — мысль о них с пометкой, что это необязательно;
   - в финальной последовательности (один фронт) — мысль о единственной текущей цели.
5. **Ступени.** Одна мысль — одна ступень. Чтобы получить «точно» по той же цели, нужен новый запрос и новое ожидание `hint.normal.precise_wait_minutes` (тест: 5 мин; по плейтесту можно сократить, например до 2 мин). Повтор той же ступени по той же цели не выдаётся, вместо него — следующая ступень или другая цель (правило очереди, п. 3 выше).
6. **Прогресс во время ожидания** таймер **не сбрасывает и не отменяет** автоматически (`hint.normal.auto_cancel_on_progress: false`): игрок мог продвинуться в одном месте и остаться в тупике в другом. Мысль всё равно созреет, а пересчёт (п. 4) сделает её полезной. Если она уже не нужна, игрок её просто не открывает или отказывается (п. 7). Вариант с автоотменой при прогрессе оставлен параметром на случай, если плейтест покажет, что лишние мысли раздражают.
7. **Отмена.** Да, без штрафа (`hint.normal.cancel_allowed: true`).
   - Тап по кнопке во время ожидания открывает маленькую плашку: «Мысль созревает, ещё около 3 мин» и кнопку «Не нужно, разберусь сама». Отмена останавливает ожидание; следующий запрос начинает его заново.
   - Готовую мысль можно открыть или отложить; в плашке готовой мысли есть та же кнопка отказа.
   - Повторное нажатие во время ожидания **не перезапускает** таймер и не ставит второй запрос в очередь: одновременно существует не больше одной мысли (ожидающей или готовой).
8. **Как показывается ожидание** (согласовать с дизайнером, `docs/design/visual-and-ux.md` 3.11):
   - вокруг кнопки «Мысли» чернильное кольцо, которое постепенно замыкается по часовой стрелке (форма, а не цвет; работает в градациях серого);
   - **цифр на основном экране нет**, чтобы ожидание не превращалось в отсчёт и не давило; оставшееся время с округлением до минуты видно только в плашке по тапу (`hint.normal.show_remaining: on_tap`);
   - «мысль готова»: кольцо замкнуто, внутри значка появляется точка-капля чернил, одна короткая вибрация 10 мс (если вибрация включена) и тихий звук пера с визуальной парой; повторных напоминаний нет;
   - на экранах головоломок, документов и блокнота кнопка видна в том же углу, её состояние меняется так же, но мысль открывается только по тапу.
9. **Учёт времени.** Ожидание считается только в активной игре: приложение на экране, не в меню паузы и не в главном меню. На экранах головоломок, документов, блокнота и в диалогах время идёт; во время роликов тоже (игрок не теряет время из-за сюжетной сцены). Состояние сохраняется (`hint.pending: { step, remaining_s }`, `hint.ready: bool`), поэтому после выхода из игры ожидание продолжается с того же места, а готовая мысль остаётся готовой.
10. **Что мысль никогда не делает** (на всех уровнях): не называет код, порядок, значение, нужный предмет, цель в сцене поиска и способ решения (запреты выше). Ожидание не может «купить» больше информации, чем ступень «точно».
11. **Журнал.** Каждая выданная мысль копируется во вкладку «Мысли» блокнота (раздел 11) и перечитывается бесплатно, без ожидания.

Почему так: нет экономики и тревоги «сберечь заряды»; игрок сохраняет контроль (сам решает, что застрял); ожидание — мягкая цена, которая оставляет шанс додуматься самому и не позволяет пролистать исследование; пересчёт в момент открытия исключает устаревшие подсказки.

Параметры (тестовые значения, подбираются по плейтесту): `hint.normal.wait_minutes` = 5, `hint.normal.precise_wait_minutes` = 5, `hint.normal.cancel_allowed` = true, `hint.normal.auto_cancel_on_progress` = false, `hint.normal.show_remaining` = on_tap.

### 3.6. Голос героини: общие правила
- Все игровые реплики героини (осмотр, неверное действие, показ логики, навигация) — внутренний голос, первое лицо, настоящее время, коротко.
- Реплики хранятся ключами локализации, RU и EN пишутся отдельно с тем же смыслом.
- Реплика никогда не содержит значение ответа в виде текста, кроме показа логики **после** решения.

## 4. Стопроцентная логика: проверка честности

### 4.1. Требования к каждой головоломке
1. **Единственность.** Решение одно. Для T01, T04, T05, T10, T17, T18 проверено решателем (скриптом). Для T06, T15, T20 проверено вручную: ни одна другая комбинация или вывод не обоснованы текстом игры так же хорошо.
2. **Выводимость.** Каждая часть ответа выводится из конкретного объекта, найденного **до** этой головоломки на любом допустимом пути по графу (проверяется по графу, раздел 7.6). Источники перечислены в карточке.
3. **Без угадывания.** Нет шагов «попробуй и посмотри». Если ответ — выбор из вариантов, вариантов не меньше 4 и неверные варианты правдоподобны, а не абсурдны.
4. **Правило задано в мире.** Правило преобразования («прибавь», «порядок по датам», «тень на час») показано или прямо следует из найденного. Правило, известное только автору, запрещено.
5. **Восстановимость на С.** Даже без обратной связи игрок на С может сам найти ошибку: все источники лежат в блокноте или в доступных локациях, а по шагам решения видно, где рассуждение могло разойтись.
6. **Нелингвистичность.** Логика одинакова на RU и EN (раздел 5).

### 4.2. Цепочка логики в карточке
Решение в карточке записывается как цепочка вида «источник → правило → часть ответа»:
```
1. CL-HALL-PAINTING: на картине {stars} звёзд → первая часть кода = {stars}
2. CL-KITCHEN-BOOK: строка «21:00 — счётчик {counter}» → правило «последние 2 цифры»
3. Итог: {code} = {stars}{counter_last2}
```
Каждая строка обязана ссылаться на объект из графа. Строка без ссылки — признак нечестной головоломки.

### 4.3. Показ логики после правильного ответа (все уровни)
- Сразу после анимации решения героиня одной фразой связывает подсказку и ответ: «Семь звёзд на картине и две последние цифры из книги Марты. Вот и код». Это поле `logic_line` в карточке, шаблон с параметрами.
- До 20 слов на RU, без новой информации, только связь найденного с ответом.
- Фраза сохраняется в блокноте в записи головоломки, чтобы игрок мог перечитать.
- Для многоэтапных — своя фраза после каждого этапа.
- Если ответ получен частично случайно (игрок подобрал), показ логики всё равно объясняет, почему ответ верный: игрок не останется с вопросом «почему».

### 4.4. Обратная связь при ошибке
| | Лёгкий | Нормальный | Сложный |
|---|---|---|---|
| Что видит игрок | отмечена неверная часть ответа + реплика героини, с каким источником она расходится («Вторая часть не сходится с записью Марты») | «неверно» + число верных частей или общая реплика («Что-то не так с порядком») | только «неверно» (звук + короткая анимация) |
| Поле карточки | `feedback.easy` (по частям) | `feedback.normal` | — |

Реплики ошибки не называют верное значение и не подсказывают правило, которого игрок ещё не видел.

### 4.5. Тест честности (обязателен для каждой головоломки)
- Тестировщик, не знающий решения, решает её на Н, затем **своими словами** объясняет, почему ответ такой. Объяснение должно совпасть с цепочкой из 4.2.
- Если тестировщик решил, но не может объяснить (подобрал), головоломку усиливают: больше вариантов ответа, обратная связь меньше похожа на «горячо / холодно».
- Если тестировщик объяснил иначе и его логика тоже ведёт к ответу или к другому ответу, это неоднозначность: переделать.

## 5. Двуязычность (RU / EN)

### 5.1. Классы
- **A — безопасно.** Решение на числах, символах мира, цветах с символами, позициях, механике. Переводятся интерфейс и реплики.
- **B — текст несёт информацию, ответ нелингвистический.** Текст пишется отдельно для RU и EN с тем же фактом, ответ одинаковый. Обязательна проверка эквивалентности.
- **C — текст в графике.** Нужна локализованная версия ассета; в карточке перечисляются все такие ассеты.
- **D — запрещено.** Решение зависит от свойств языка.

### 5.2. Запрещено (D)
- акростихи, первые и последние буквы;
- число букв, длина слова как ответ;
- алфавитный порядок и сортировка по названию;
- анаграммы, палиндромы, рифмы, каламбуры, игра слов, омонимы;
- ответ-слово, вводимое с клавиатуры;
- буквенные координаты и буквенные коды;
- грамматический род как подсказка;
- форматы, читаемые по-разному: ДД.ММ / ММ/ДД, 12/24 часа, десятичная запятая и точка, фунты и килограммы.

### 5.3. Разрешённые приёмы
- числа словами («в седьмой раз» / «for the seventh time»);
- ответ — выбор из карточек или изображений;
- знаки мира с таблицей «знак → число / пиктограмма» (`docs/story/story-bible.md`, раздел 7);
- буквенный шифр — отдельный ключ и шифротекст для каждого языка;
- «третья строка, число в ней» разрешено, «третья строка, пятое слово» запрещено;
- имена и названия одинаковы на обоих языках, транслитерация — по глоссарию сценариста.

`logic_line`, `feedback.*` и `nav.*` тоже пишутся отдельно для RU и EN и проверяются на то, что не раскрывают больше на одном из языков.

### 5.4. Оформление в карточке
```
### RU / EN
- Класс перевода: B
- Как работает на RU: в письме «…приду ровно через {hours} часа после боя часов…»; игрок считает время по часам в холле.
- Как работает на EN: «…I'll come exactly {hours} hours after the clock strikes…»; то же вычисление.
- Ответ одинаков: да — {target_time}.
- Сложность одинакова: RU 46 слов / EN 41 слово; ключевой факт во 2-м предложении.
- Локализуемая графика: нет / список ассетов.
- Пометки переводчику: «{hours} — параметр, не заменять словом».
```
Окна документов рассчитываются на RU (длиннее EN на 10–30 %); рукописные шрифты поддерживают кириллицу и латиницу в одном стиле.

## 6. Навигация 360° и читаемость панорам

### 6.1. Устройство
- Каждая локация состоит из 1–4 **точек обзора** (`VP-<LOC>-<n>`). В точке игрок видит панораму 360°.
- **Свайп** поворачивает голову (по горизонтали без ограничений, по вертикали в пределах `pitch_limit`, тест: −45°…+40°).
- **Тап по указателю перехода** — шаг в соседнюю точку или в соседнюю локацию.
- **Тап по активному объекту** — подойти и открыть крупный план. Если объект далеко, тап сначала переносит в ближайшую к нему точку обзора.
- Горизонтальное поле зрения — параметр (`fov_h`, тест: 90°).

### 6.2. Привязка объекта к панораме
Каждый активный объект (`HS-...`) имеет:
- `vp` — основная точка обзора, из которой он открывается;
- `yaw` (0–360°, 0 — направление взгляда при входе в точку) и `pitch`;
- `size_deg` — угловой размер зоны касания;
- `visible_from[]` — другие точки, откуда он виден (тап оттуда ведёт к `vp`);
- `lead` — чем объект привлекает внимание без подсветки (свет, движение, звук с визуальной парой, контраст), если нужно.

### 6.3. Правила, чтобы активные объекты не терялись
1. **Комфортная полоса.** Активные объекты находятся в пределах `pitch` −30°…+25°. Объект выше или ниже (люк в потолке, плита пола) обязан иметь `lead`: падающая пыль, полоса света, звук с визуальной парой, реплика героини при входе.
2. **Сектор входа.** Главный объект локации виден в стартовом направлении взгляда при первом входе (±45° от `yaw` = 0).
3. **За спиной.** Объект в секторе 135°–225° от направления входа либо виден ещё из одной точки, либо имеет `lead`.
4. **Плотность.** Не больше 8 активных объектов на точку обзора и не больше 3 в одном экране (90°). Чаще — разбить на две точки.
5. **Размер.** Зона касания не меньше 48 dp при `fov_h`. Если объект меньше, зона расширяется невидимо, а сам объект ставится на контрастный фон.
6. **Визуальный язык активного.** На всех уровнях активные объекты имеют единый художественный признак, о котором договариваемся с дизайнером (`docs/design/`): например, тёплый блик на металле, лёгкая пыль на бумаге, отличный от фона контраст. На С это единственный признак, поэтому он не может быть слабым.
7. **Без двойников.** В сцене нет неактивных копий активного объекта (пять одинаковых ящиков, из которых открывается один). Либо все открываются, либо неактивные явно другие (заколочены, без ручек).
8. **Шов и полюса.** Активные объекты не стоят на шве панорамы (`yaw` ≈ 0/360 у ассета) и у полюсов (потолок, пол прямо под ногами).
9. **Смена состояния видна.** Объект, ставший активным позже (ящик открылся, механизм заработал, дверь приоткрыта), меняется визуально из той точки, откуда его обычно видно, а лучше и из точки входа в локацию.
10. **Указатели перехода видны на всех уровнях.** Двери и проходы имеют постоянный ненавязчивый указатель. Потайные ходы получают указатель только после открытия.
11. **Подсветка по уровням.** Л — мягкое свечение активных объектов и стрелки у края экрана к неосмотренным объектам вне кадра; Н — кнопка «Осмотреться» (раздел 3.3); С — ничего, только правила 1–10.

### 6.4. Плейтест читаемости (для С)
Для каждой точки обзора: тестировщик без подсветки за 2 мин находит все активные объекты. Пропущенный объект меняется: позиция, `lead`, контраст. Результат записывается в карточку точки обзора.

### 6.5. Быстрое перемещение (предложение, согласовать с дизайнером)
Свободная карта и дальние связи требуют частых возвратов. Предлагается план усадьбы в блокноте с переходом в любую посещённую локацию (в точку входа) на всех уровнях. Это не подсказка: план показывает только посещённые места и открытые проходы. Без него возврат за источником дальней связи занимает минуты ходьбы, что плохо для коротких сессий.

## 7. Открытая карта: ворота, тупики, предметы

### 7.1. Ворота
Ворота (`GT-...`) — то, что запирает часть карты. Типы:
| Тип | Что запирает | Пример |
|---|---|---|
| `item` | дверь или тайник открывается предметом | ключ от флигеля |
| `puzzle` | проход открывается решением | кодовый замок сторожки |
| `knowledge` | нужно знать информацию (код, место), предмета нет | «Совиный путь начинается с часов» |
| `event` | сюжетная сцена после действия игрока | разговор после найденной улики |

Правила:
- Ворота срабатывают **только от действия игрока**: никаких таймеров и «прошло достаточно времени».
- `event`-ворота привязаны к конкретному действию (решена головоломка, предъявлена улика), сцена запускается при следующем входе в нужную локацию или сразу.
- Каждые ворота перехода между актами — головоломка или предмет с рейтингом не выше среднего для текущего акта: ворота не должны быть самым трудным местом акта.

### 7.2. Открытые фронты
- В любой момент после стартовой зоны у игрока открыто **2–4 задачи в разных местах** (узлы фронта на обязательном пути, раздел 3.5).
- Один фронт допустим только в начале (обучение, первые 10–15 мин) и в финальной последовательности.
- Больше 5 фронтов не допускается: игрок теряется.
- **Правило передышки:** если во фронте есть головоломка с рейтингом 5, в нём же есть задача с рейтингом ≤ 2 или исследование новой локации.
- Однотипные тяжёлые задачи (T08, T05, T10) не открываются одновременно больше одной.

### 7.3. Нет тупиков
- Из любого достижимого состояния достижим финал. Проверяется скриптом по графу (7.6): перебор состояний или случайные прогоны (тест: 10 000 случайных порядков).
- Нет односторонних дверей, которые отрезают обязательный контент. Если сюжет закрывает проход (обвал, запертая сторожем дверь), второй путь к тому же месту открывается в том же действии.
- **Несколько путей где уместно:** ворота с `any_of`, где одну и ту же информацию можно получить из двух источников, или в одну зону ведут два входа (например, потайные ходы становятся короткими путями между этажами). Ориентир — минимум 2 таких развилки на акт. Развилки одинаковы на всех уровнях сложности.

### 7.4. Ключевые предметы нельзя потратить не туда
- Предмет применяется только к своим целям. Применение не туда ничего не расходует и не меняет: предмет возвращается в инвентарь, героиня говорит реплику.
- Предмет исчезает из инвентаря только после **последнего** правильного применения. Многоразовые предметы (лупа, отвёртка) остаются навсегда.
- Комбинирование необратимо только если ни один из исходных предметов больше нигде не нужен. Иначе результат можно разобрать или исходник остаётся.
- Нет расходуемых предметов в ограниченном количестве (спички, масло): либо бесконечный запас, либо ровно одно применение и одна цель.
- Сюжетная потеря предмета (кража фрагмента чертежа в сюжете) допустима, только если предмет больше не нужен ни в одной головоломке **или** вся его информация уже лежит в блокноте («Снимки», «Документы»). Отметить в карточке события. Требует проверки со сценаристом.

### 7.5. Дальние связи остаются доступными
- Ни одна локация с источником подсказки или дальней связи не закрывается навсегда.
- Источник дополнительно хранится в блокноте с качеством, достаточным для решения («Снимки» или «Документы»), на всех уровнях.
- Финальная зона (башня) связана с домом проходом, который не закрывается до финальной сцены обвинения. Точка невозврата — только после того, как все головоломки, кроме финальных, решены, а все источники для финальных лежат в финальной зоне или в блокноте.

### 8.1. Акты вместо глав

### 8.2. Кривая сложности при свободном перемещении
- Порядок головоломок внутри акта игрок выбирает сам, поэтому кривая строится по **глубине**: сколько ворот нужно пройти до головоломки. Самые сложные головоломки акта стоят за 1–2 воротами внутри акта, а не у входа.
- Незаконченные головоломки старых актов остаются: игрок может вернуться. Новые объекты в старых локациях (появились после событий) получают рейтинг текущего акта.
- Распределение рейтинга по игре (Н): 1 — 15, 2 — 26, 3 — 31, 4 — 21, 5 — 11 (итого 104).
- Новый тип впервые появляется с рейтингом ≤ 2 и с короткой репликой героини, объясняющей управление.
- Ориентир общего времени чистого решения: Л ~4–5 ч, Н ~7–8 ч, С ~11–13 ч (без ходьбы, диалогов и роликов).

### 8.3. Темп и сессии
- Целевая сессия 10–20 мин. Глав и эпизодов нет, но в каждом акте у игрока есть короткая цель-ориентир в блокноте («Понять, куда ушёл Тарн»), которая меняется по `event`-воротам.
- Автосохранение: после каждой головоломки и этапа, при переходе в другую локацию, при сворачивании. Сохраняется точка обзора и направление взгляда.
- После паузы — экран «Ранее в деле»: текущая цель и 2–3 последние находки. На Л и Н ещё и список открытых вопросов, на С — только запертые объекты.
- Чередование обеспечивается составом фронта (правило передышки, 7.2): рядом с тяжёлой головоломкой всегда есть лёгкая задача, исследование или разговор.

## 9. Дальние связи

### 9.1. Определение
Дальняя связь (`LL-xx`) — подсказка из акта I–II, которая применяется в актах IV–VI. Цель на игру: 4–6 связей (в сюжете их 6), 1–2 участвуют в метазагадке.

### 9.2. Правила честности
1. **Источник заметен как объект, но не как головоломка.** Отдельный осматриваемый предмет с крупным планом. Герой реагирует фразой, которая делает деталь запоминающейся, но не объясняет назначение.
2. **Источник не исчезает** (раздел 7.5): локация доступна до конца и копия лежит в блокноте.
3. **Эхо в середине.** Между источником и применением хотя бы одно напоминание (акт III–IV): тот же символ на другом предмете, упоминание в письме, реплика персонажа.
4. **Узнавание в приёмнике.** В месте применения есть явная отсылка к источнику (тот же орнамент, символ, фраза).
5. **Нет ложного замка в начале.** Если источник похож на загадку, блокнот помечает его как наблюдение («Странный узор на раме. Пока не понятно, к чему он»).
6. **Нет преждевременного решения.** Значение источника уникально и не решает другие головоломки по ошибке.
7. **Параметризация.** Значение в источнике — параметр приёмника.

### 9.3. Помощь по уровням
| | Лёгкий | Нормальный | Сложный |
|---|---|---|---|
| При осмотре источника | «Открытые вопросы» с пометкой «может пригодиться» + автозапись значений | «Открытые вопросы» | копия в «Документах» / «Снимках» |
| При встрече приёмника | запись «Похоже на то, что я видела в {location}» со ссылкой | ничего | ничего |
| Навигационная подсказка | сразу: точно, локация и объект-источник | по запросу с ожиданием (3.5): сначала локация источника, при повторном запросе — объект | нет |

### 9.4. Реестр
`docs/levels/long-links.md`: `LL-ID | источник (объект, акт, локация, VP) | эхо | приёмник (PZ, акт) | что переносится | копия в блокноте | локация доступна до конца`. В карточке приёмника поле «Дальняя связь» обязательно. Каждая связь проверяется тестировщиком, не знающим о ней заранее.

### 10.3. Хранение релизных значений
Тестовые значения — в карточке и `values/test.yaml`. Релизные — отдельно (`docs/levels/release-values/` или вне публичной части репозитория, по решению владельца); в карточке только пометка «подбираются позже». Релизные значения не совпадают с тестовыми ни в одной головоломке.

## 11. Блокнот

Разделы (кнопка в углу экрана, все уровни, если не сказано иначе):
- **Улики** — автоматически.
- **Документы** — копии всего прочитанного, открываются в любой момент.
- **Снимки** — кнопка-камера на крупном плане.
- **Коды и числа** — Л автоматически; Н и С — игрок выделяет фрагмент тапом; на Л ключевые фрагменты выделены цветом.
- **Открытые вопросы** — Л и Н автоматически, С только запертые объекты.
- **Решённое** — для каждой головоломки фраза `logic_line`.
- **Мысли** (Л и Н) — журнал полученных навигационных подсказок, перечитывается бесплатно.
- **План усадьбы** — если принят раздел 6.5.
- **Метазагадка** — после первого фрагмента.
- **Заметки игрока** — свободный текст и стикеры на снимках.

## 12. Чек-лист перед тестом
- [ ] Все поля карточки заполнены, значения — параметры, тексты — шаблоны.
- [ ] Цепочка логики: каждая строка ссылается на объект графа; единственность проверена (раздел 4).
- [ ] `logic_line` и `feedback.easy/normal` написаны на RU и EN и не раскрывают ответ до решения.
- [ ] Источники доступны до головоломки на любом пути по графу.
- [ ] Предметы нельзя потратить не туда; предмет исчезает только после последнего применения (7.4).
- [ ] Головоломка не закрывает навсегда локацию с источником подсказки (7.5).
- [ ] Скрипт графа: нет тупиков, во фронте 2–4 задачи, правило передышки соблюдено.
- [ ] Л и С отличаются от Н минимум по двум осям; граф на всех уровнях одинаков; помощь на Л не показывает ответ.
- [ ] Навигационные фразы `area / precise / ready / missing` есть и не содержат решения.
- [ ] Точка обзора: yaw/pitch в комфортной полосе или есть `lead`; объект читается без подсветки (плейтест 6.4).
- [ ] Класс перевода указан, нет приёмов D, локализуемые ассеты перечислены.
- [ ] Зоны касания не меньше 48 dp, решение без щипка, цвет дублирован символом, звук — визуалом.
- [ ] Время на Н соответствует акту; если больше 5 мин, есть этапы.
- [ ] Для дальних связей: копия в блокноте, есть эхо, приёмник отсылает к источнику.
- [ ] Тест честности 4.5 пройден; механика не повторяет узнаваемую головоломку.
