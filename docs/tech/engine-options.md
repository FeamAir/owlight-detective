## 0. Что требует игра от технологии (кратко)

- **Панорамы 360°**: кубическая карта (6 граней по 2048, мастер 4096), свайп с инерцией, наклон ±40°, поле зрения 75–100°, тап-зоны по `yaw/pitch/size_deg`, чернильные метки переходов, растворение 0,35–0,6 с. 3D в реальном времени не нужно: это «картинка на кубе» плюс наложенный UI.
- **Много 2D-интерфейса и текста**: крупные планы, документы, блокнот, сумка, диалоги с портретами, субтитры с ID (решение №11), около 100 экранов головоломок.
- **Контент в данных**: граф прогрессии, карточки головоломок, `values/test.yaml` / `values/release.yaml`, `difficulty_profile.yaml`, реплики `DLG-...` с текстом RU/EN и полем `audio` (каркас 7.6, 10.2).
- **Объём ассетов всей игры** [Оценка]: 130–150 точек обзора, каждая 6 граней по ~300–600 КБ (WebP/JPG) или ~11 МБ в памяти (ASTC). В сумме 0,4–1 ГБ, это больше лимита базового модуля AAB (200 МБ), значит, для релиза нужен Play Asset Delivery или докачка. Для среза (одна локация, 3–6 точек) это 20–40 МБ, проблемы нет.
- **Монетизация**: в игре нет рекламы и магазина подсказок. Возможен только один экран «Полная версия» с Google Play Billing (дизайн 3.16).

## 1. Варианты

### Вариант A. Godot 4 (GDScript), экспорт в Android и в веб

| Задача | Как делается |
|---|---|
| Панорама 360° | `Camera3D` внутри куба с 6 гранями или `Sky` с `PanoramaSkyMaterial` (развёртка). Свайп меняет `yaw/pitch` камеры. Около 100 строк кода. |
| Тап-зоны | Перевод точки касания в направление луча, затем сравнение с `yaw/pitch/size_deg` объекта из YAML. Метки — `Sprite3D` или Control-узлы, спроецированные на экран. |
| Переходы | `Tween` и шейдер растворения между двумя кубами. |
| Головоломки, UI | Сцены `Control` (UI-узлы Godot): удобный редактор, анимации через `AnimationPlayer`. |
| Диалоги | Своя простая система на данных (рекомендую) или плагин Dialogic. |
| Локализация RU/EN | Встроенный `TranslationServer` (CSV/PO). Кириллические шрифты подключаются без проблем. |
| Сохранения | JSON в `user://`. |
| Контент в YAML | Встроенного YAML нет. Решение: Python-скрипт при сборке конвертирует YAML в JSON и проверяет граф (PyYAML в среде есть). Файлы сцен `.tscn` текстовые, их можно править без редактора. |
| AAB / Google Play | Экспорт AAB встроен (Gradle build). Нужны Android SDK, JDK 17+ и export templates. Поддержка 16 КБ страниц памяти и актуального target API есть в свежих 4.x [Проверить]. Play Asset Delivery из коробки нет, нужен плагин или докачка. |
| Billing | Официальный плагин Godot Google Play Billing. |
| Слабые Android | Хорошо при рендерере Compatibility (OpenGL ES 3). Пустое приложение весит около 25–35 МБ [Оценка]. |
| Веб-сборка | Есть (WebGL 2, рендерер Compatibility). Первая загрузка тяжёлая: движок 20–40 МБ wasm [Оценка]. В Chrome на Android работает. |
| Лицензия | MIT, бесплатно, без отчислений. |
| Команде | Лёгкий язык, быстрый редактор. Но вёрстку UI и анимации удобнее делать в GUI-редакторе, а у нас его нет (см. раздел 2). |

### Вариант B. Unity 6 (C#)

| Задача | Как делается |
|---|---|
| Панорама 360° | Skybox или Cubemap-материал и камера с вращением. Типовое решение, много примеров. |
| Тап-зоны, переходы | Как в A: математика `yaw/pitch`, UI поверх (uGUI или UI Toolkit), анимации через DOTween или Animator. |
| Головоломки, UI | Мощный редактор, но UI-вёрстка в Unity многословная. |
| Диалоги | Своя система на данных или Yarn Spinner / Ink. |
| Локализация | Пакет Unity Localization (String Tables, импорт CSV). |
| Сохранения | JSON в `persistentDataPath`. |
| Контент в YAML | Нужна сторонняя библиотека (YamlDotNet) или конвертация в JSON при сборке. |
| AAB / Google Play | Самый отработанный путь: AAB, Play Asset Delivery через Addressables, target API выставляется в настройках [Проверить]. |
| Billing | Unity IAP (официальный). |
| Слабые Android | Хорошо, но сборка тяжелее: пустая весит 20–40 МБ [Оценка]. |
| Веб-сборка | Unity Web работает на мобильных браузерах, но долго грузится и требует много памяти. Как ссылка для владельца — посредственно. |
| Лицензия | Personal бесплатна при доходе и финансировании до 200 тыс. $ за 12 месяцев; выше нужен Pro, около 2 000–2 300 $ в год за место [Проверить]. Runtime Fee отменён в 2024 году. |
| Команде | Большой и тяжёлый редактор, C#. Обязательна активация лицензии через аккаунт Unity. |

### Вариант C. Веб-стек: TypeScript + Three.js (панорамы) + HTML/CSS (UI), упаковка в Android через Capacitor

| Задача | Как делается |
|---|---|
| Панорама 360° | Three.js: камера внутри куба с `CubeTexture`, свайп и инерция, `pitch_limit`, `fov`. Около 200 строк своего кода. Альтернатива — готовый просмотрщик (Photo Sphere Viewer или Marzipano), но свой код проще подогнать под чернильные метки и растворение. |
| Тап-зоны | Объекты из YAML (`yaw/pitch/size_deg`). Метки и зоны — HTML-элементы, которые каждый кадр проецируются из 3D-направления на экран. Зона касания легко делается не меньше 48 dp. |
| Переходы | Две панорамы и прозрачность (растворение), анимация FOV для «наезда». |
| Головоломки, UI | HTML/CSS/SVG: сильная сторона веба. Текст, шрифты с кириллицей, слои, перетаскивание, вращение колец, адаптация под разные экраны. Для сложных анимаций — Canvas или PixiJS. |
| Диалоги и субтитры | Данные `DLG-...` (ID, RU, EN, `audio: null`) — прямо YAML/JSON. Позже добавить `<audio>` к реплике — без переделки (решение №11). |
| Локализация | Ключи и строки в YAML/JSON, без дополнительных библиотек. Текст в графике накладывается вёрсткой, как требует дизайн 0.5. |
| Сохранения | В браузере — `localStorage`/IndexedDB. В APK — нативное хранилище через Capacitor Preferences/Filesystem, чтобы система не стёрла данные. Схема сохранений версионируется. |
| Контент в YAML | Лучше всего: YAML читается напрямую (`js-yaml`), а одна и та же схема и валидатор графа работают и в сборке, и в тестах. |
| AAB / Google Play | Capacitor создаёт обычный Android-проект (Gradle) с ассетами внутри APK, поэтому работает офлайн. AAB собирается штатно, target API задаётся в Gradle [Проверить]. Для релизного объёма (0,4–1 ГБ) нужны install-time asset packs. То, что WebView может читать файлы из них, надо проверить прототипом до 2-й локации — **это главный технический риск варианта**. Запасной путь — докачка с CDN при первом запуске. TWA (обёртка над сайтом) не берём: нужен постоянный хостинг, а офлайн работает хуже. |
| Billing | Плагины Capacitor (например, cordova-plugin-purchase или RevenueCat) [Проверить]. |
| Слабые Android | Панорама — это 6 текстур, для GPU это лёгкая нагрузка. Риски — память и WebView: текстуры нужно сжимать в KTX2/Basis (на устройстве превращаются в ASTC/ETC2), в памяти держать только текущую и соседние точки. Без этого 18 несжатых граней 2048² займут около 300 МБ. Задержка звука в WebView выше, чем в движке, но для субтитров и эмбиента это некритично [Оценка]. |
| Веб-ссылка для владельца | Лучший из трёх: обычная страница, грузится за секунды, обновляется без установки. |
| Лицензия | Three.js, Capacitor, Vite — MIT. Бесплатно. |
| Команде | Самый низкий порог: всё — текстовые файлы. Сценарист и левел-дизайнер правят YAML, видят результат обновлением страницы. Нет визуального редактора сцен: тап-зоны ставятся числами `yaw/pitch`, поэтому нужен простой режим разработчика «тапни по панораме — получи yaw/pitch» (1–2 дня работы). |

### 2.3. (б) APK для установки на Android
Ни в одном варианте APK в среде **сейчас не собрать**: нет Android SDK, а источники Google закрыты прокси. Пути:
1. **Открыть в сетевых настройках среды доступ** к `dl.google.com` и `maven.google.com` (для Godot ещё `github.com` с релизами). Объём установки [Оценка]:
   - Android: cmdline-tools, platform-tools, build-tools, одна платформа — около 0,6–0,8 ГБ; кэш Gradle и AGP — ещё 0,3–0,5 ГБ; первая сборка 10–20 мин;
   - Godot: редактор около 100 МБ и export templates около 1 ГБ;
   - диска в среде достаточно: свободно около 60 ГБ.
2. **Собирать APK в GitHub Actions**: на раннерах Ubuntu Android SDK уже установлен. Владелец скачивает APK из артефактов сборки. Для этого сессии нужен доступ к репозиторию (сейчас не включён). Это удобный постоянный вариант: каждая правка → новый APK.
3. Собрать на компьютере владельца или разработчика с Android Studio (для Unity — единственный путь).

Подпись: отладочный APK подписывается автоматически сгенерированным debug-ключом, он не попадает в репозиторий. Релизный ключ загрузки (upload key) хранит владелец вне репозитория; для релиза включаем Play App Signing.

## 4. Рекомендация

**Рекомендую вариант C (TypeScript + Three.js + HTML/CSS, Android через Capacitor)**, при условии, что у команды владельца нет сильного опыта в Godot или Unity (вопрос 1).

Почему:
1. Игра — статичные панорамы и много 2D-интерфейса и текста. Это задача, где веб сильнее движков, а 3D-движок в реальном времени почти не используется.
2. Решение №14: владелец смотрит срез. По ссылке в браузере телефона — без установки и сразу после каждой правки.
3. Весь контент (граф, головоломки, значения test/release, реплики с ID и полем `audio`) живёт в YAML и читается напрямую. Сценарист и левел-дизайнер меняют файлы, программист не нужен.
4. В нашей среде можно собрать, протестировать (unit-тесты логики и сквозные тесты в headless Chrome) и показать скриншоты. Для Godot и Unity сейчас нельзя даже запустить проект.
5. Бесплатно, без лицензионных порогов.

Риски варианта C и как их снять до 2-й локации:
- объём ассетов в AAB (asset packs + WebView) — прототип на срезе с 1 «тяжёлым» asset pack; запасной путь — докачка;
- память на слабых телефонах — KTX2-сжатие и выгрузка дальних точек; замер на 1–2 недорогих телефонах владельца;
- если риски не снимаются, логика и данные переносимы: формат YAML и контракт ассетов не зависят от движка, перенос в Godot затронет только слой отображения.

**Запасной вариант — A (Godot 4)**: если у команды есть опыт Godot или если на прототипе WebView окажется слабым. Unity (B) имеет смысл, только если первая игра владельца сделана на Unity и в команде есть Unity-разработчик.

### 4.1. План среза первой локации (вариант C) [Оценка]

Локация среза по графу — ворота и сторожка (`LOC-GATE`; `PZ-GATE-01` требует источник из `LOC-ALLEY`). Точный состав определяет левел-дизайнер. Следующая локация видна, но заперта (решение №15).

| Этап | Что получается | Объём |
|---|---|---|
| 0. Основа | проект, схемы данных (JSON Schema для YAML), валидатор графа (7.6: нет тупиков, источники дальних связей не закрываются, коды уникальны), тесты, сборка веб-версии | 2–3 дня |
| 1. Панорама | куб, свайп с инерцией, наклон, FOV, тап-зоны и чернильные метки из YAML, переходы с растворением, режим разработчика «yaw/pitch по тапу», заглушки граней скриптом | 4–5 дней |
| 2. Экраны | главный экран, выбор сложности (не меняется в игре, №4), пауза и настройки, крупный план, режим чтения документа | 3–4 дня |
| 3. Диалоги | вводная сцена, портреты, субтитры с ID, поле `audio`, RU/EN-переключатель | 3 дня |
| 4. Сумка и блокнот | инвентарь, комбинирование, записи и коды, «Открытые вопросы», флаги, граф прогрессии | 4–5 дней |
| 5. Головоломки среза | 2–4 головоломки как компоненты на данных (`values/test.yaml`, `release.yaml`, `difficulty_profile`), показ логики и обратная связь по уровням, «Мысли» с таймером ожидания на Н (№13) | 5–7 дней |
| 6. Сохранения | автосохранение, версия схемы, тесты: решение головоломок, ветвления, загрузка старого сохранения | 2–3 дня |
| 7. Показ | веб-ссылка, APK через Capacitor (нужен доступ к SDK или CI, раздел 2.3), проверка на 1–2 телефонах | 2–3 дня |
| **Итого** | | **5–7 недель** одного программиста, без учёта финальной графики |

Порядок показа владельцу: после этапа 1 — ссылка «походить по заглушкам»; после этапа 5 — полный срез; после этапа 7 — APK.

## 5. Вопросы к владельцу

1. **На каком движке сделана ваша первая игра в разработке, и кто её делает?** Если команда уже знает Godot или Unity, это весомый довод за этот движок.
2. Вас устраивает смотреть срез **по ссылке в браузере телефона**, а APK получить позже? Или APK нужен сразу?
3. Можно ли **включить в среде доступ к `dl.google.com` и `maven.google.com`** (Android SDK) и, при выборе Godot, к `github.com`? Или собирать APK в **GitHub Actions** (тогда нужно разрешить сессии доступ к репозиторию)?
4. Где разместить веб-ссылку: GitHub Pages (репозиторий публичный?) или ваш аккаунт Cloudflare Pages / Netlify? Ссылку лучше закрыть паролем или держать в тайне, ведь в срезе тестовые ответы.
5. Какие телефоны есть для проверки, особенно недорогие? Минимальную версию Android определяем по ним и по данным аналитика.
6. Модель продажи (бесплатно с открытием полной версии или платно сразу) — для среза не нужна, но влияет на интеграцию Billing позже.
7. Какой Blender-художник и когда начнёт панорамы? Срез идёт на заглушках; контракт ассетов из раздела 3 стоит согласовать с ним заранее.
